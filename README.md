# 看台 · V4

替球迷持续跟队，识别值得知道的变化，用有出处的资料解释比赛。

这是本地单用户足球助手。V4 只保留「球队动态」和「询问助手」两个主板块：动态页集中展示消息、赛程、近期表现和球队背景；助手页支持连续追问和本地历史。设置、资料来源、关注主题及球队资料编辑统一收进设置弹窗。

新版使用中文界面、清晰字号和球场立体交互；消息以中文要点展示，来源通过链接访问。四支内置主队补齐本地队徽、中文背景和出处，另有 20 支常见球队的本地队徽目录。助手查到的原文继续保存到 SQLite，有实际已读来源的结构化消息另行归档，供后续检索及动态卡片复用。

**请使用 http://127.0.0.1:8765/ 正式应用。** `prototype/index.html` 是静态设计演示，不保存模型配置。原型现已撤掉模型输入和假保存入口，提供正式应用链接。

## 本地启动

日常使用：双击桌面的 **看台 Touchline**，或项目内 **启动看台.cmd**。服务已经运行时会复用；没有运行时会启动并打开正式应用。

需要 Python 3.11+；首次构建/开发需要 Node.js 22+。也可在 Windows PowerShell 中运行：

```powershell
.\start.ps1
```

常规启动复用已安装依赖与已有页面，不再每次安装和重建。首次环境缺失或执行 `./start.ps1 -Setup` 时才准备依赖。`./start.ps1 -NoBrowser` 启动但不打开浏览器。服务在后台运行，日志保存在 `output/service-*.log`；关闭网页不会停止服务。打开 **http://127.0.0.1:8765**。

设置页可创建桌面快捷方式，也可选择登录自启（默认关闭）。登录自启只启动本地服务，不自动打开浏览器。电脑关闭时不会运行任务。

开发时也可按以下步骤在终端前台运行，按 Ctrl+C 停止：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
npm ci
npm run build
.\.venv\Scripts\python.exe -m uvicorn server.main:app --host 127.0.0.1 --port 8765
```

macOS/Linux 使用 `python3` 创建环境，并把 Python 路径替换为 `.venv/bin/python`。

前端开发：后端保持运行，另一个终端执行 `npm run dev`，打开终端显示的地址；`/api` 请求代理到 8765。页面正式构建保存在 `dist/`，由后端同源提供。默认仅绑定本机，不包含面向公网的登录、账号隔离和运营设施。

## 第一次使用

1. 在演示空间体验球队动态、事件关注、比赛看点与跟队问答。演示回答明确标记为规则演示，不会消耗模型额度。
2. 切换到真实资料，在设置里选择你关注的球队。
3. 打开设置中的“资料来源”，添加球队相关的 RSS 或文章网页，或手动粘贴已有资料。手动录入资料需要标题、正文和所属球队；原始链接与发布时间可选，未知时间不会被编造。
4. 在设置选择 **Chat Completions 或 Responses 协议**，填写服务地址、模型名称、API 密钥并保存。分级连接检查会实际验证连通、生成、工具调用和结果续答；测试本身不会隐式保存。也支持提供兼容接口的本地模型服务，无密钥时可留空。
5. 点击“球队动态”的“更新动态”取得新闻和官方赛程；点击消息的“问助手”，或切换“询问助手”获得中文解读。比赛日历可直接发起前瞻或复盘。未知数据留空。
6. 在设置的“关注主题”中建立具体主题，例如球员伤情或转会进展。服务运行时按周期检查；没有新原文时跳过重复模型解读。可暂停、恢复、调整或立即检查。
7. 设置中可开启定时更新；自动生成解读默认关闭，开启后会使用模型额度。球队资料可在设置的“球队资料”中编辑，个人修改不会被基础资料升级覆盖。

模型测试会发送三次短请求：生成文本、调用测试工具、读取工具结果后续答。普通文本连通不等于支持工具调用。服务地址可填基础路径（如服务商说明中的 `/v1`），也可填写与所选协议匹配的完整端点；地址与协议冲突会明确报错，不自动切换。模型名称使用服务商给出的准确 ID，本项目不会自动指定付费模型。DeepSeek 可在高级设置选择是否开启深度思考，温度默认不发送，以提高不同模型的兼容性。

## 自己实现的部分

- **采集**：直接读取 HTML/RSS/Atom，提取正文和来源时间，保留原文与 URL；限时、限量并校验请求目标。
- **资料处理**：本地正文指纹去重、事件证据与时间线、已读和关注状态。复杂的跨来源传闻自动归并仍需进一步验证，手动导入可明确追加到已有事件。
- **联网工具**：从球队官网、官方站点地图及公开 RSS 发现候选、读取原文和刷新球队来源。当前内置阿森纳、利物浦、巴萨、国米；其他球队可配置自己的来源。动态页面优先使用公开的内嵌文章数据与官方索引，不安装浏览器或绕过登录。
- **本地工具**：读取球队背景、检索本地证据、读取证据原文、比较事件进展、读取比赛上下文。模型只能调用注册工具，不能执行任意代码。
- **技能**：`agent_skills/` 中可维护的五份技能：跟队问答、球队简报、赛前观察、赛后复盘、事件跟进。自动路由可选择初始技能，模型可在白名单内组合工作方法，不能扩大资料权限。
- **交付工具**：`submit_answer` 校验摘要、事实条数和实际已读引用，然后由程序渲染一份简洁答复，避免把模型执行过程和重复草稿交给用户。新增来源概览工具，可检查各来源的可用性与新鲜度。
- **原文支持核对**：关键事实附实际原文摘录，先检查摘录来自当前可读原文，再独立检查事实、概览和分析是否获支持。未通过时最多修复一次，仍不足则保守降级；界面只保留必要的待确认提示与来源链接，详细核对记录留在本地。
- **官方比赛适配器**：自研四队赛程/结果读取，阿森纳读取官网自身的公开只读原始数据，其他适配器解析官方页面结构；不让模型猜日期或比分。阿森纳、利物浦可读取已发布且同场匹配的官方首发；巴萨和国米首发尚不可用。
- **球队图表**：近期胜平负与进失球来自已收录的完场比赛。先选近5/10场，再排除缺少比分的记录；明确缺失数量，不用更早场次补齐。保留逐场日期与来源，避剧透时整体隐藏。
- **Harness**：模型选择工具 → 本地验证并执行 → 回传结果 → 继续或停止。保留轮次、超时、取消和引用检查，无额外编排平台。
- **存储**：SQLite 持久化，真实与演示资料隔离。模型密钥在本机服务端加密存储，网页只回读是否已配置。密文和本地加密密钥均位于本机，因此不等同于操作系统密钥保险箱。

## 使用边界

全新安装的真实空间初始为空，可直接从内置来源收集已支持球队的消息。网页可能限流、依赖浏览器执行或无法提取；失败会显示原因，可改用其他来源或手动导入。应用不会把演示消息补进真实空间，也不会在模型失败时伪造模型回答。

采集调度仅在本地服务运行且开启自动更新时工作，不包含关机后的云端任务或推送。原文支持核对是消息可靠性检查，不等于独立事实认证，更不能保证每个足球推断都正确。原始来源仍可能有错，缺数据和冲突会明确呈现。

避剧透针对赛果标题、赛后资料及已结束比赛结果进行过滤。自动采集的赛前新闻若仅部分段落含历史赛果，可提供明确标注的安全节选；原始正文保持不变。手动明确标为剧透的资料不自动放开。该功能采用保守文本规则，不能保证识别所有隐含表述；显式本场复盘才读取所选比赛的完整关联资料。

`data/` 保存本地资料、设置和凭据，不应提交到 Git 或公开分享。此目录已加入 `.gitignore`。服务地址是你授权的模型接收方，运行时会向它发送当前问题及必要的球队资料。
