# 球队资料与素材

`catalog.json` 是浏览器球队名称解析、服务器初始球队库及公开采集来源的共同数据源，现内置 96 支球队。国家用于浏览分组，不代表球队在任何赛季的联赛归属。

每队包含中文背景、城市、官网、背景资料出处、常见中英文名称、真实本地队徽及队徽出处。已核验的历史创立年份按官网口径保存；水晶宫与纽卡斯尔涉及多种历史起点，使用说明文字，不用一个整数覆盖其历史。没有当季阵容、主教练、赛程或积分的静态数据。

## 创立年份、主场与昵称的来源

这三项按 **一个字段一个权威源** 补齐：Wikidata（CC0）负责成立年（`P571`）与主场（`P115`），昵称（`P1449`）同样取自该处但只接受拉丁字母的结果——维基数据的声明保留录入语言，阿斯顿维拉的昵称原文是希腊语「Οι Χωριάτες」，混在中英对照的资料表里不如留空。每队补齐后在 `background_sources.wikidata` 留下实体编号、来源页面、许可与核验日期。

96 支球队全部有成立年与主场，昵称 34 支；阿森纳、利物浦、巴萨、国米四队使用本地手写中文资料，不被该流程覆盖。

补全由 `scripts/enrich-clubs.py` 执行，离线运行、只写入缺失字段。它不猜：搜索会返回同名实体（博洛尼亚是城市、尼斯是地点、摩纳哥是国家），因此候选必须通过 `P31` 类别校验，且**按具体性排序取最优**而非取第一个通过的。这一步出过一个必须记住的错误：切尔西本身的 `P31` 是 `Q103229495`（association football club），早期版本漏列该类，于是跳过了正确实体、选中了 `Q2669653`「切尔西发展队与青训学院」——两者都是「足球俱乐部」。类别表不完整会把一个正确答案静默变成错误答案，因此候选改为打分排序，并在续跑时重新校验已存结果。

`attribution.json` 记录每个在目录中使用的图片的原始地址、来源页面、文件大小、SHA-256 与核验日期。英格兰球队标识复用已收录的英超官方球队目录；其他标识来自俱乐部官网及其对阵资料。拜仁与马竞标识取自皇家马德里官网的球队资料，罗马标识取自 AC 米兰官网的球队资料，其具体来源与署名逐条保留。

所有队徽统一放在 `clubs/` 下：阿森纳、利物浦、巴萨、国米四个旧路径（`/assets/<文件>`）在根目录保留原文件并在 `compatibility_assets` 登记用途，目录本身指向 `clubs/` 下的同一份文件。目录下每个图片文件必须被目录引用或在 `compatibility_assets` 登记，`tests/test_club_library.py` 会因此失败——此前目录里有四个无人引用的文件，其中三个是重复副本。

`real-madrid.svg` 与 `paris-saint-germain.avif` 曾随内置目录写入球队档案，因此继续保留原真实文件作为旧 URL 兼容。新目录使用全彩皇马 PNG 和巴黎 PNG，升级不改写用户已保存的图片地址。旧文件的来源与校验值单独记录在 `compatibility_assets`；构建时应随 `public/assets/` 一并发布。

队徽和标识的商标及图形权利归所属俱乐部或相关权利方。公开可下载不表示开放授权，也不表示本项目与俱乐部、赛事方存在合作或获得认可。本目录不包含球员肖像、商业摄影图库或俱乐部照片的批量转载。

公开采集入口包括俱乐部新闻页及 The Guardian 球队 RSS；原有阿森纳、利物浦的 BBC RSS 继续保留。RSS 仅用于发现文章，其摘要不应视为完整报道。官网可能使用动态页面或限制自动访问，运行时应报告具体失败并保留原站入口。各来源内容的更新速度、覆盖范围和页面可读性由原站决定。

2026-09-12 的网络核验中，30 个 Guardian 球队 RSS 均返回有效 XML 和 20 条文章条目；30 个官网新闻入口有 26 个返回 HTTP 200，曼城、马竞、罗马返回 HTTP 403，拜仁请求超时。HTTP 200 只说明入口可访问，不代表动态文章列表或所有正文都可自动读取；访问状态逐源保存在 `research_sources[].access_review`，运行时结果应优先于这次核验。

资料核验日期：2026-09-12。历史背景来源逐条记录在 `profile_sources`。本地队徽随应用交付，无需浏览器跨站请求图片。数据升级只补充缺失字段，保留用户修改、明确留空的资料、自建球队、关注选择及停用的来源；启动时不把历史背景伪装为最新新闻。
