# 资料与照片复核

代码负责判定，模型负责取舍。**模糊项**才是这条方向处理的事：代码已经算出的结论不会交给模型重判，模型接手的是代码判不了的那部分。

## 谁做什么

| 问题 | 谁回答 |
| --- | --- |
| 这是谁、有没有字段、来源有没有回答过 | **代码**，规则判定，不交给模型 |
| 这些字段值写进哪一行、写什么 | **代码**，只由来源写入 |
| 哪个候选更可能、一次未命中是限流还是检索词错 | **模型**，在这条方向上做判断 |
| 下一轮该重试谁、怎么重试 | **模型**给出动作，代码执行 |

**模型不写任何字段值。** 它返回的是动作，不是数据：不提供姓名、出生日期、国籍、年份、检索词或照片地址，也不引入清单之外的新来源。

## 复核覆盖的四块

| 域 | 代码已给出的结论 | 剩下要判断的 |
| --- | --- | --- |
| 照片画面 | 身份、许可、地址由来源核对完毕 | 画面本身是否可用（清晰、人像、无水印或错误裁切） |
| 球员事实 | 阵容源给了哪些字段、缺哪些 | 缺出生日期／国籍的球员是否值得专项查找，先查谁 |
| 中文名 | `zh-hans` 标签、繁简归一化、身份证明 | 未命中的原因是限流、检索词，还是来源确实没有 |
| 球队资料与队徽 | `missing_fields`、队徽的 `status`（缺来源／站外／本地） | 缺口该补哪一项、队徽缺的署名能否从已有记录恢复 |

**队徽不做画面复核。** 队徽是商标图形，字节已计入署名记录的哈希，没有"这张脸是谁"的等价问题；它开放的问题只有覆盖度——有没有来源与署名——而那正是代码能算的。

## 先看清代码已经给出的结论

用 `photo_queue` 看照片缺口，用 `get_team_data` 看 `components`（含 `portraits.acceptance`、`profile.missing_fields`、`profile.crest`）。两者都是只读本地视图，不联网。照片缺口已按原因分类：

| 类别 | 含义 | 是否值得再试 |
| --- | --- | --- |
| `fix_route` | 传输未读取成功 | **值得**，换时间 |
| `fix_ambiguous` | 多个候选无法分辨 | **值得**，来源数据变化后可能定下来 |
| `fix_namesake` | 被同名球员挡住 | 不要对同一来源重试，换来源 |
| `fix_roster` | 阵容缺核对所需的事实 | 不是照片的事，走"球员事实"那一项 |
| `fix_source` | 来源确实没有此人 | 不要重试 |
| `fix_nothing` | 来源已明确拒绝 | 不要重试 |

**不要把这些分类重新判一遍。** 它们已经是代码算过的归因，重新判断只会把"来源说没有"当成"再试一次"。

## 发起复核

`review_maintenance` 处理这件事：

- **省略 `action`**（或 `action=status`）：只读本地复核记录，不联网，返回 `reviews`、`retry_now`、`investigate` 和可直接转述的 `note`。
- **`action=refresh`**：发起一轮复核。这是付费调用，且必须先在设置里把模型指派给**复核角色**；未指派会明确报错，不会静默换用别的模型。

复核会同时看两类东西：**有来源的照片**（判断画面本身是否可用）和无图的**缺口项**（判断下一轮该怎么推进）。缺口没有图片可看，但它是"重试谁"这个决定的主体。

## 结论是动作，不是形容词

| action | 含义 | 下一步 |
| --- | --- | --- |
| `keep` | 代码的结论成立 | 不用动作 |
| `retry` | 值得再试一次 | 按 `retry_hint` 换来源、换检索词或换时间；`effort` 说明现在还是稍后 |
| `investigate` | 重大怀疑或信息互相矛盾 | 交给用户或进一步核查，**不要**自己下结论 |

三条边界，越界即错：

- **`retry` 不是删除许可。** 它让某件事进入下一轮排队，不撤回任何已核验的照片或字段；身份、许可与地址仍只由来源写入。
- **读不到就当没读。** 照片无法下载或格式不对时返回的是 `unreadable` 里的一条说明，不是 `retry`。把网络故障当成"这张图很糟"会误伤好照片。
- **结论只对当前这一轮的候选集成立。** 每轮上限 12 项，没进清单的不代表已经通过。

## 与验收的分工

`components.portraits.acceptance` 由**代码**计算覆盖率与缺口归因，`review` 由**模型**判断画面与重试方向。向用户解释时不要合并成一句"程序认为照片不合格"——两者回答的是不同问题，混在一起会让用户以为覆盖率判定依赖模型。

## 不要做的事

- 不要用复核结论改写球员资料、球队资料或队徽记录。
- 不要在 `acceptance.actionable_count` 已经是 0 时继续发起重试。
- 不要因为模型说 `retry` 就对同一来源、同一检索词重复发起；`retry_hint` 说明的正是"该换什么"。
- 不要把 `investigate` 或 `uncertain` 的推断写成结论。
- 不要试图给队徽找图或判断队徽像不像——那是权利与来源记录的问题。
