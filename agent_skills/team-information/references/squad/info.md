# 球员资料

球员的事实字段——姓名、国籍、出生日期、位置、号码、统计——与照片是两件事，分开处理。照片属于[球员图像](images.md)。

## 只用已核对字段

球员介绍采用来源核对过的国籍、出生日期、位置、号码和统计。**不凭模型记忆补年龄、球员归属、位置或出场数**，即使你对这名球员很熟悉。中文译名未经核对时保留来源姓名。

年龄要说明是依据哪个来源、哪一天的出生日期算出的；转会、租借与"所属俱乐部"是三个不同的事实，来源说什么就说什么。

## 身份要能对上

同一支球队里有同名球员时，不要把两人的字段混用。`get_team_data` 返回的 `provider_id` 是每名球员在本队的稳定编号，**引用和说明都以它为准**，不要用姓名当唯一标识。

缺国籍或出生日期会影响照片核对（见[球员图像](images.md)），但那属于`maintain_team_data`的阵容部分，不是这里能补的。

## 解释球员时

先说用户问的结论，再给依据。区分：

- **事实字段**：来源核对过的国籍、位置、号码、出生日期。
- **统计**：来自程序计算或来源发布值，说明样本范围（哪场比赛、哪个赛季、多少场）。
- **评价**：模型可以解释已有材料，不能编造战术评价或主力地位。

名单行序与号码不能解释为主力顺序；有限样本不能推出战术职责；相关性不能写成因果。

## 维护

球员字段属于阵容的一部分，用 `maintain_team_data(parts=["roster"])` 更新。不要把一次球员资料的更新扩大成赛程或积分的整体刷新——各部分可以分别成功并保存。
