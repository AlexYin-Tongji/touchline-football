# 球队信息

依据可追溯的数据回答球队与球员问题，把球队、赛季、比赛范围和更新时间对应清楚。模型解释已有事实，维护工具负责核对与保存事实字段。

## 先看数据范围，再按问题选一条

先读[数据范围与维护](references/data-scope.md)，再用 `get_team_data` 或已有球队上下文确认本题所需资料。**已有有效快照先用**；只有缺失、过期或失败的部分才调用本轮允许的 `maintain_team_data`。

然后只加载与问题对应的那一条，不要一次展开全部：

| 问题 | 方向 | 读 |
| --- | --- | --- |
| 某球员是谁、位置、号码、统计 | 球员 → 资料 | [球员资料](references/squad/info.md) |
| 球员照片、缺图、照片来源与许可 | 球员 → 图像 | [球员图像](references/squad/images.md) |
| 俱乐部、赛程、积分榜、避剧透 | 球队 | [球队](references/team.md) |
| 胜负、进失球、近期表现与样本范围 | 数据 | [数据](references/data.md) |

球员方向先看[球员](references/squad.md)确认是哪一类，再进到具体那份。

## 维护按部分进行

`maintain_team_data(parts=...)` 的部分包括 `roster`（阵容）、`schedule`（联赛及有参赛证据的欧战赛程）、`standings`（完整联赛积分榜）和 `portraits`（照片）。未指定时由工具选择缺失或需重试的核心部分。

**各部分可以分别成功并保存。** 某部分失败不丢弃其他成功资料；失败时解释仍有效的旧快照并保留其原始更新时间。缺一张照片不应触发整套阵容与赛程的重复更新，也不要重复催促同一失败来源。

维护后重新读结果，**不把失败或空字段解释成球队没有球员、比赛或统计值为零**。

## 交付

先给用户所问的结论，再说明相关数据范围、日期与来源。依问题选择球员介绍、赛程说明、统计对比或维护结果，不机械列出所有字段。保留必要局限；相关性不能写成因果，名单行序与号码不能解释为主力顺序。

执行共用[阅读协议](../reader_protocol.md)，按工具实际提供的证据提交引用。球队维护不会解除避剧透，也不授权模型直接修改球员归属、比分、排名或统计数值。
