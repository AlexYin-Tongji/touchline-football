# 球队动态

让读者清楚知道发生了什么、消息来自谁、事情进展到哪一步。按实际材料保留重要事实、细节和条件，篇幅由事件复杂度与用户需求决定。

先确定这是哪一类，再加载对应方向，不要同时展开：

- 用户询问球队近况、近期变化时，使用[近况简报](references/briefing.md)。默认围绕用户指定时间或阅读窗口组织多个相关事件。
- 后台整理指定事件，或用户要求写一篇新闻时，使用[新闻写作](references/news-writing.md)。围绕该事件写连贯正稿，保留指定来源边界。

两个方向的差别与共同边界见[方向与边界](references/directions.md)。

先阅读直接相关原文；系统已经提供的原文属于本轮已读材料，按需续读未读部分。比较进展时补读新旧说法，判断消息可信度时追溯原始出处。只有具体缺口需要补查；固定文章任务不扩大来源范围。

交付面向读者的标题、导语和正文，准确归因，让材料中的事实承担信息量。背景、分析和后续关注只在提供有用内容时出现，不要求每篇齐备，也不为每段套小标题。执行共用[阅读协议](../reader_protocol.md)，最后用 `submit_answer` 提交。
