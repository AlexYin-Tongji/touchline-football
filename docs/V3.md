# 看台 V3：一眼看懂、自动跟队、关键消息能核对

## 本轮目标

1. 首屏只呈现「今天最重要的变化」「下一场」「建议接下来做什么」，每区内容有数量上限。长回答、来源管理、工具轨迹和设置均按需展开。
2. 补充球队标识、比赛/伤情/转会/核对/提醒等一致图标，按钮仍配文字，不用只有装饰用途的图标。保留 V2 白底、深墨与亮蓝方向，改善层级和密度。
3. 自动取得赛程、结果与可核对的阵容/人员消息，建立比赛基本信息来源与更新状态。用官方网页的结构化数据与公开源，不接第三方足球分析 API，不编造无法取得的字段。
4. 关键结论必须关联实际原文片段，再做独立的来源支持程度检查；矛盾、推测、媒体说法与官方原文分开。无法支持的强断言需要重写或移除，不把引用编号存在当成消息真实。
5. 基于来源变化、比赛时间及待确认事项生成推荐：值得读什么、赛前看什么、哪些主题适合继续跟进。明确推荐理由、依据和时效，可忽略。自动更新开关、周期和状态可见。
6. 赛前/名单更新/赛后按同场比赛衔接，保留原判断。事件记忆保留新旧主张及需要等待的下一项证据。
7. 一键启动、桌面快捷方式和可选登录自启；常规启动复用已有依赖与构建。设置和原文留在本机，保存现有模型配置。
8. 缓存来源与已有简报，按变化更新。以真实数据、真实模型和固定质量案例验收，控制额外调用。

## V3 增量协议（保持 V2 向后兼容）

Settings新增：`automation:{enabled:boolean=false,interval_minutes:number=60,sync_matches:boolean=true,generate_brief:boolean=false}`；`verification_enabled:boolean=true`；`verification_timeout_seconds:number=45`。自动推荐始终根据已有可见资料计算，不需要为了显示卡片调用模型。启用自动更新时，服务运行期间按设置更新；未变化不重复生成简报。

Match扩展：`source_url?:string,source_name?:string,source_match_id?:string,updated_at?:string,synced_at?:string,kickoff_confirmed?:boolean,lineups?:{status:'confirmed'|'unavailable',home?:string[],away?:string[],source_url?:string,updated_at?:string},availability?:[{name,status,source_url,evidence_id?,updated_at?}],data_warnings?:string[]`。可保持旧status scheduled/finished；延期、时间未定等用data_warnings/kickoff_confirmed显式表达。未知比分/名单保持空。

Recommendation：`{id,team_id,mode,kind:'read'|'preview'|'review'|'follow'|'verify'|'setup',title,reason,priority:'high'|'normal',evidence_ids:string[],match_id?:string,event_id?:string,query?:string,created_at,expires_at?,dismissed?:boolean}`。

GET `/api/state` 增加 `recommendations:Recommendation[]`、`automation_status:{last_checked?,last_error?,running,next_check?,last_run_id?}`、`service:{version:'3.0.0',running:true,autostart_enabled:boolean}`。

- POST `/api/teams/{team_id}/sync` → `{matches_updated:number,evidence_added:number,lineups_updated:number,errors:string[],synced_at}`；获取比赛/球队资料，无 LLM。
- POST `/api/recommendations/{id}/dismiss` ← `{dismissed:boolean=true}`；不删除资料。
- POST `/api/automation/run` ← `{team_id?:string}` → `{started:true,status}`；立即运行一次已配置更新，刷新新闻/比赛并更新推荐，是否生成简报取决于generate_brief。
- GET `/api/service` → 本机服务与自启状态；POST `/api/service/shortcut`创建桌面入口；PUT `/api/service/autostart` ← `{enabled:boolean}`，仅在用户显式操作后修改登录启动项，默认关闭。

Run扩展：`verification?:{status:'supported'|'partial'|'insufficient'|'unavailable'|'not_requested',checked_at,claims:[{id,text,verdict:'supported'|'unsupported'|'conflicting'|'uncertain',reason,quotes:[{evidence_id,quote}]}],warnings:string[]}`、`structured_answer?:{summary,facts,analysis,unknowns}`。声明是否得到原文支持是来源核对结果，不等同于独立事实认证。前端可从每条事实打开原文摘录和核对说明。

## 模块责任

- Root：server/main.py/storage.py、server/automation.py/recommendations.py/service_control.py、启动脚本、文档、集成测试与最终真实验收。
- 数据 Agent：新server/fixtures.py，必要的小改research.py/ingestion.py，tests/test_fixtures.py。完成自动赛程/结果/阵容数据工具与实际源验收；不要改main/storage/agent/frontend。
- 质量 Agent：server/verification.py、agent.py/agent_tools.py、agent_skills/**、tests/test_verification.py/test_agent*.py。完成原文片段与语义支持核对、受限修复及工具分工。不要改main/storage/provider前端，若需provider小改先协调。
- 前端 Agent：src/**、必要的package更新和public/assets/**（球队标识及出处），前端布局、图标、推荐与自动设置、核对UI、比赛信息、启动控制。不要改server。

## 数据函数约定

`async fixtures.sync_team(store,team_id)->{matches_updated,evidence_added,lineups_updated,errors,synced_at}`。新比赛写入matches（live），新来源记录可写evidence（live）。root Store新增collections recommendations/fixture_sources，可用get_meta/set_meta缓存。尽量不改旧Match字段含义。

`fixtures.get_team_status(store,team_id)->dict`：读取上次同步元信息，不联网。过期、部分失败、未知名单明确报告。

固定源适配器优先支持用户关注阿森纳，同时核对利物浦、巴萨、国米。任何不支持的情况明确返回，不用手动样例代替真实数据。

## 质量函数与边界

由质量Agent在现有submit_answer流程接入，默认真实模式启用，演示明确未调用模型。先核对quote确实来自本次可读原文，再独立调用现有用户模型做claim与quote的支持程度检查。核对过程可取消、有超时；最多一次修复，避免无限循环与无界成本。未通过的事实不以成功样式交付，网络证据中的命令始终无效，密钥不出现在上下文、日志或代码。

不得以大量模拟测试代替真实消息质量。需要对真实发布会/伤情/赛事资料人工抽查，保留错误案例供后续回归。
