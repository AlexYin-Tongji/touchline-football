## V9.3.0 — 2026-10-19

第一个对外发布版本。功能边界不变，重做的是界面与代码的组织方式。

**设计系统**
- 新增 `src/styles/tokens.css`：字号收敛为 12 档、行高 4 档、间距 4px 基准、圆角 4 档、五级投影。组件样式表只允许引用变量，不写裸数值。
- 删除 5 条 `font-size: 0.68rem … 0.88rem` 的裸值——它们是团队栏沿用的另一套尺度，与此处的中文排版冲突。
- 中文标题统一衬线，界面文字统一无衬线；`letter-spacing` 只留给西文大写与英文名。原来"联赛排名"这类中文标签也带着 1.2px 字距，方块字被拉开后像散架。
- 灰阶收敛为两档：`--muted` 是正文级说明，`--faint` 是时间与单位，两者在 `--paper-sunk` 上都达到 4.5:1。

**样式表拆分**
- `v7-base.css` + `v7-app.css`（5,433 行）拆成 `tokens / base / shell / feed / team / assistant / settings` 七个文件。
- 新增 `scripts/check-css-coverage.mjs`：列出 TSX 用了但样式表没有的类名。V8.7 拆分时丢掉过整组 `<b>` 选择器，这类失配编译通过、运行不报错，只能靠对比发现。
- 清掉三处旧结构遗留下来的死规则（`.club-hero-glare`、`.rail-bottom`、`.settings-intro`）。

**外壳**
- 窄屏主导航从顶部横排改到底部固定标签栏。390px 下三个中文标签挤成两行、图标压字。
- 左栏删掉球场装饰图形与"不止九十分钟"标语：它不携带操作，却把"发现更多球队"推到视线外。
- 页头右侧去掉"我的足球主场"装饰文字，只留设置入口。

**球队页**
- 去掉 hero 的指针倾斜与跟随高光。资料页不该跟着鼠标晃。
- 更新动作收敛成一行：`更新 / 补全` + 上次更新时间。补全进度条只在展开或运行中渲染——之前按钮、折叠条、加载行三层都在说"点击启动"。
- "正在准备名单、照片与比赛资料"只在尚无可显示内容时出现。名单已经渲染 29 人时它仍然挂着，读起来像卡住了。
- 资料字段从 `space-between` 改成两列网格：四列排开时标签与值被拉到两端，眼睛要横跳。
- 进球图横轴改用俱乐部短名 + 日期。原先十列全队名竖排重叠，任何字号都救不回来。
- 赛程行去掉未开赛的 "VS"，比赛名称移入对手名下方，主客标签与"主场作战"不再重复。
- 亮眼球员改为中文名在前、原名在后，与阵容卡同一阅读顺序。

**动态**

**修复**

**封面**
- 打开页面先显示开场封面：品牌、一句话说明、一个「进入看台」按钮，点一次淡出进入应用。窄屏下按钮占满整行。
- 封面版本号与 `package.json`、`build_info.VERSION` 同源手写，发版时三处一起改。

**这轮立下的边界：**
- **同一段轨道上的颜色规则必须带轨道前缀。** 只写 `i.result-W` 时，任何后出现的 `… > i` 通用规则都能覆盖它，而浏览器不报错。
- **界面取值只从 `tokens.css` 来。** 组件样式表里出现裸字号或裸颜色，就是下一轮"同一屏五种灰"的起点。
- **中文排版不加字距。** 需要拉距的是西文大写，不是方块字。
- **装饰不占操作位。** 左栏底部的标语、hero 的倾斜、标题右侧的图标，都不携带信息却挤占视线与点击区域。
- **同一件事只说一次。** 状态句、进度条、加载行三者同时出现时，读者只会觉得页面卡住了。
- **选择器失配靠脚本发现，不靠肉眼。** 改完样式跑一次 `check-css-coverage.mjs`。

## V9.2.0 — 2026-10-19

问答模块重写。同一组 5 个真实问题，平均耗时 171s → 85s，模型请求 10.2 → 3.2，完成率 4/5 → 5/5。

**慢在哪**（基线实测，不是推测）
- 一次提问最少四次跨网络模型往返：草稿轮、被打回改用 `submit_answer`、提交轮、独立原文支持核对。核对默认开启，实测每次额外 5–40 秒。
- 同一响应里的多个工具调用串行执行，每个工具前后各写一次完整 run 到 SQLite。
- 问答向模型广告 20 个本地工具 + 6 个委派工具；前端 1.6 秒轮询全量 run，答案跑完才出现。

**差在哪**
- 外站正文落盘即删（内存留 1 小时），实测本库 207 篇新闻有正文 0 篇。重启后检索只剩标题。
- 检索打分是二值子串求和：无词频、无 IDF、无长度归一化、无时间衰减、无来源层级；中文是逐字 bigram，无停用词，"新闻/消息"这类词几乎必然命中。
- `ENTITY_ALIASES` 只有阿森纳一队 24 人。中文问"马丁内斯"，系统识别不出任何实体，整句退化成噪声 bigram，排序把一篇讲别人的文章排到第一。

**检索**
- 新增 `search_index`：BM25 + 语料级 IDF + 7 天半衰期 + 来源层级加权 + 同事件按标题键折叠。索引在落库删正文**之前**建立，磁盘上只存词频、段落字符区间、实体与俱乐部标识，不含句子。
- 中文分词去掉虚词与跨词 bigram；新增中英主题桥（帅位→manager verdict、缺阵→ruled out），主题词分强弱两档。
- 新增 `entity_names`：从阵容快照的 `name`/`name_zh` 生成别名，中文名能命中英文标题；共享姓氏（马丁内斯、费尔南德斯、弗莱彻）进 ambiguous 集合，不参与门控。
- `search_evidence` 改走索引，返回命中片段而非固定前 300 字；`scripts/rebuild-search-index.py` 提供重建与回填。

**上下文与循环**
- 新增情境简报：球队、近三天 12 条标题、阵容、近 5 场、读者偏好，约 1,860 字，替代原来的原始 JSON 转储。
- 问答提示词从约 6,000 字压到 3,200 字，删掉工具巡检式说明与重复的引用规则。
- 提问前按索引预读 4 篇相关原文，并行读取；同一响应内的只读工具并行执行。
- 联网检索上限 2 次；第 3 轮提醒"够了就提交"，第 5 轮要求直接交付；历史只带最近 3 轮且答案截断。

**交付**
- 语义核对默认只对新闻开启。问答要开启用新键 `conversation_verification`，`verification_enabled` 继续只管新闻。本地引用完整性检查不随开关关闭。
- `answer` 为主，`evidence_ids` 提到顶层，`facts` 降为可选。

**技能分层**
- 问答树登记 10 个方向：`match.preview`、`match.review`、`transfer.status`、`injury`、`tactics.explain`、`team.state`、`team.form`、`event.watch`、`directions`、`answer.writing`。
- 每个方向声明能力集，加载后工具面收窄（战术题 7 个、状态题 7 个、伤情题 11 个、泛问 12 个）。
- 路由命中的方向会真正登记到 `topics_used`——此前 `route_skill` 只返回 workflow 名，方向从未加载，能力集形同虚设。
- `read_article` / `research_news` 的能力标签改挂 NEWS：它们读的是 `discover_news` 发现的候选，挂在 EVIDENCE 下会让不设 NEWS 的方向拿到一个必然失败的工具。

**界面**
- 等待时显示最近完成的 3 步真实进展，不再是一句静态提示。

**这轮立下的边界：**
- **空正文索引会自我固化。** 重建索引只能拿到标题；若按证据的真实 `body_hash` 写一条空正文记录，之后真正读取会被"哈希未变"短路，索引永远停在空正文。必须标 `body_owed=true`、`body_hash=null`。与"缓存窗口被读成身份判决"是同一类错误。
- **跨语言桥的原料是阵容快照，不是静态别名表。** 快照的 `name`/`name_zh` 覆盖率约 94%，是唯一能自动维护的中英对照；静态表只覆盖一队，扩表即漂移。
- **共享姓氏不参与门控。** 与照片板块的同名者规则一致：不猜人。
- **方向不登记就不收窄。** 路由返回 workflow 名不等于加载了方向；两处必须同时改。
- **流式逐字输出与引用校验冲突。** 字一旦显示，就无法在提交时因引用不成立而撤下。因此不做逐字流，改为过程步骤即时可见。
- **`team_maintenance` 是球队页的查询侧**，不是维护任务，尽管名字像。维护类判断统一用 `NON_QUESTION_SKILLS`。

## V9.1.0 — 2026-10-18

设置收成一个默认模型，动态的取图、去重与写法重做。

**设置**
- 六个模型角色（动态 / 问答 / 球队维护 / 核验 / 照片 / 复核）收成一个 `active_model`。旧 `model_roles` 原地保留、不再读取，迁移只写一次哨兵键，回滚不用改数据。
- 参数按模型存：上下文窗口、最大输出、推理等级、温度、超时。下发按协议区分——`chat_completions` 用 `reasoning_effort`，`responses` 用 `reasoning.effort`，`anthropic_messages` 用 `thinking.budget_tokens`。温度只在显式开启且没有推理等级时发送。
- 新增「检测连接」：跑一次真实往返，不是探测 `/models` 是否 200。
- 来源密钥分两类。`requires_key` 缺失即不可用；`optional_key` 缺失仍可用，只是降级（TheSportsDB 免费档返回替换过的样例数据）。后者不该被过滤掉，其密钥有效性只能靠**身份核对**判断，不能靠 HTTP 200。付费档走 v2 与 `X-API-KEY` 头，密钥不进 URL——带密钥的地址会被失败记录引用，而那些记录比请求活得久。

**动态 · 配图**
- `extract_feed` 现在读订阅源自己声明的图（`media:content`、`media:thumbnail`、`enclosure`、`itunes:image`）。此前完全没读，只能靠跟进文章页，而跟进条件是正文比摘要长。
- 认不出正文容器时不再整条返回：`<head>` 里的 `og:image` 与带图注的 `<figure>` 仍然有效。
- 懒加载页面：`src` 常是 `data:` 占位符，原先 `a or b or c` 只取第一个非空值，真图永远不会被选中。
- 图片身份按**资产**计算，不按地址。ESPN 的 `?img=` 代理、BBC 的 `/live/<uuid>`、Metro 的上传名主干各有一条规则；后端的去重与前端 `uniqueImages` 必须同规则，否则同一张照片的两个裁切会重新并排。

**动态 · 去重**
- 事件聚类的门槛从「单实体 + 伤情/转会 + 标题相近」放宽为「共享实体 + 时间窗 + 标题重合」，并可跨语言按「同一人 + 同一数字 + 两天内」合并。旧规则下，一场发布会由四家媒体各写一篇时永远并不起来。
- 新增 `feed_grouping`：哪几条卡片是同一件事交给模型判断。模型只看到编号、标题、导语片段、来源名与时间，返回分组与代表卡片；它**不写任何内容**，合并后卡片的标题、导语、图片都来自已有卡片，被并入卡片的来源全部保留。编号越界、重复分组、lead 不属于自己那组一律丢弃；模型失败时不写入任何东西，规则兜底。
- URL 比较统一走 `article_url`，与报告快照同尺。

**动态 · 写法**
- 事件标题与类型进入提示词（此前只有球队与时间），并明确说明那只是收集时的分类、不是事实。同一条消息重写后，标题从要点清单变回单一主线，分节扩展并写进了对方主帅的说法。
- 新增「具体高于全面」：有原话、数字、场景就写出来，不概括成「表达了不满」；但不为生动添加原文没有的修辞。

**这轮立下的边界：**
- **不做审核门控。** 这是信息聚合平台：给出内容与来源，真伪由读者判断。`news_coverage.py` 整份实现但**没有调用点**，不要接上——接上等于每条稿件多一轮付费模型调用，只为判断完整性。接过一次，已按要求撤掉。
- **模型可以判断"这几条是不是同一件事"，不能写内容。** 分组的输入是编号与元信息，输出是编号；任何字段都直接来自已有卡片。
- **图片身份是资产，不是地址。** 同一张照片的尺寸变体必须合并，两篇不同文章的图不能合并——尺寸标记只从文件名与最后几段路径剥离，正文路由里的词不动。
- **正文是临时的，不是漏存。** 外部来源只留 `body_hash`，正文在内存里放 60 分钟。任何"事后比对两篇是否同文"都要重抓，不能假设库里有正文。

## V8.9.0 — 2026-10-13

修掉球队页卡顿与三处数据缺陷，并把模型接进球队自己的资料链路。

**通用复核回路（照片、球员信息、球队资料、队徽）：**
- 分工是固定的：**代码给结论，模型做取舍**。这是谁、有没有字段、来源有没有回答过 → 代码；哪个候选更可能、一次未命中是限流还是检索词错、下一轮重试谁 → 模型。
- **动作是行动，不是形容词**：`keep` / `retry`（带 `retry_hint` 与 `effort`）/ `investigate`。存"不好"没人能执行，存"换检索词再试"才是下一步。旧的 `ok`/`needs_rework` 已废弃。
- **只有已有来源的照片进入复核**：带 `photo_url` 无 `photo_source_url` 的行被排除，否则模型答案会顶替它从未做过的来源核对。
- **模型不写任何字段值**，不引入新来源，不撤回已核验照片。
- **读不到就当没读**：下载失败或格式不符记 `unreadable`，不是 `retry`——把网络故障当成"图很糟"会误伤好照片。
- **缺口没有图也要能裁**：否则一个坏图会取消整轮可回答的复核。
- **队徽不做画面审查**：字节已计入署名记录的哈希、权利属于俱乐部，没有"这张脸是谁"的等价问题。

**四条性能与正确性修复：**
- `decisions` 按队保留 50 条终态（原本 82 行 / 2.17 MB，单条约 26 KB，liverpool 一队占 64 行）。**在 `finish()` 同一事务内裁剪**——两个并发 finisher 不能各自看到"满 50"而留下 51 条。运行中的行不裁。
- `/state?view=summary` 收窄 `matches`（当前队 + 关注队，每队上限 24）；`teams` 保持全量 96 行，裁掉会坏界面。
- `should_continue` 的 `max_attempts` 原是死代码（无人传 `attempts`），接上真实轮次计数，与上次验收结果存在一起。
- `_apply_photo` 返回值被忽略 → 现在把「来源答了一张、被更强的源压回去」记成 `kept_stronger_source_count` 与来源对。**不记录球员编号**：读者需要知道这轮行为是否正确，不需要知道跳过了哪几行，而球员 id 在这里会是一句未经核验的身份断言。

**中文名繁体边界：** `_wikidata_label` 回落 `zh` 时可能是繁体，而 `cjk_label` 只校验"是 CJK 字符"。新增 `server/wikidata_zh_hans.json`（Unihan `kSimplifiedVariant` 一次生成后随仓库发布，运行时不联网），剔除自身是简化目标的简繁通用字（`著`/`裡`/`復`）。**未能完全归一化的标签留空而非半转换。**

**三个核实后不成立的指控**（记下来免得重犯）：grid 无虚拟化（渲染的是阵容约 30 人，不是 96）；4 秒轮询永久轮询（完成路径会清 `enabled`）；`updated_count` 受返回值影响（它是行内容与 before 快照的比较）。

## V8.8.0 — 2026-10-12

球员照片的四类缺陷，病根相同：**缓存过期被读成了身份被否定**。

1. 缓存一到期就清空照片。
2. 整队刷新时会跳过所有缓存重发请求。
3. 「阵容缺出生日期」这种没发请求的结论也会擦照片。
4. 完成与判定共用一个 7 天窗口。

**边界：**
- **完成态与临时结论用不同 TTL**：完成 30 天，判决 1 天，可重试的失败 15 分钟。
- **同名遮挡成为独立状态**：整年出生日期不符的同名者仍被拒绝，但明确标注"被同名球员挡住，需换来源"，而不是含糊的多候选。
- **技能从单文件变为一棵树**，加载一个方向会收窄工具面（图像方向 16 → 11 个工具），并把本方向真正需要的后台工具放出来；作用域仍优先。

## V7 及更早

V7 的核验设计**已废弃**：它假设"核验得足够严，输出就可信"，于是把大量机制建立在"这个说法是否成立"上。这是错误的位置——我们既不掌握事实，也没有资格替用户裁决。`verification.py` 会**删除**未获支持的事实，V8 移除了这个动作。

V7 的具体版本记录已随 `V7_8_1_CLEANUP.md` 移除。需要时按标签检出，例如 `git show v7.8.0:docs/RELIABILITY_V7_6.md`。

**从 V7 继承下来、仍然生效的东西：** 五个来源层级、避剧透、凭据只存服务端加密、来源失效后阻止旧内容重新展示、缺照片保留占位而不是猜。
