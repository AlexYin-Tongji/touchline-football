## 1. 这个项目在做什么

「看台」是本地、单用户的足球信息助手。三件事：动态（中文消息流）、球队（阵容/赛程/积分/照片）、问助手（对话）。

**关键定位，重构的全部依据**：

> 它做**信息整合**，不做**事实认证**。用户看到的是「谁在什么时候说了什么」，真伪由用户自己判断。

这条推翻了 V7 的设计。V7 把大量机制建立在「这个说法是否成立」上（语义核对、删改未通过的说法、修复循环、恢复检查点），既不成立也不该由我们做。V8 把这些删掉，换成**逐条来源标注**。

完整推理见 `docs/DESIGN_PRINCIPLES.md`，那是顶层依据，改动前先读它。

## 2. 已经建好的地基（不要推翻重做）

### `server/provenance.py` — 溯源层
- `SourceTier`：`OFFICIAL / DATASET / PRESS / COMMUNITY / DERIVED`。**层级决定措辞，不决定资格**。社区源不是低一等的媒体源，它的价值在时效与现场性。
- `Claim`：字段级主张，两个时钟分开（`fetched_at` 取回时间 / `observed_at` 来源声明时间），TTL 由字段名推导并可被比赛时间加速。
- `Relation`：`parent_club / current_club / former_club / youth_club`。**这条解决了一个真实的误判**——租借球员同时属于两支球队，此前被当成数据错误丢弃。
- `_REGISTRY` + `register()`：域名层级由代码授予，`tier_for_url()` 查表。URL 优先于 id，所以社区源不能借用官方 id 提权。
- 5 条不变量写死在代码里：无来源拒绝 / 未登记域名不得自称强层级 / `DERIVED` 必须记录算法与输入 / tier 不取自输入 / 未知 tier 拒绝。

### `server/providers/` — 来源层
统一信封 `Answer(items, gaps, cached, spent)`。**失败是 gap，不是空成功**——"没找到"和"请求失败"必须可区分，否则故障会显示成沉默。

已接入：ESPN(DATASET)、Wikimedia(DATASET)、TheSportsDB(COMMUNITY)、Reddit(COMMUNITY)、球迷博客 RSS(COMMUNITY)、football-data.org(DATASET，需 key)。

能力查询：`sources(capability=..., tier=...)`。**缺凭据的来源不对外提供**（`configure_credentials` 注入密钥查询）。

加新来源：写一个 `@provider(...)` 装饰的类，加入 `providers/__init__.py` 的 `_MODULES`。层级在装饰器里声明即完成登记。

### `server/collection.py` — 采集调度
按**超期倍数**排序（不是绝对时长），所以一个月前的比分排在一年前的生日之前。无时间戳的排最前。`plan()` 按预算取用，取不下的报告为 `skipped` 而不是静默丢弃。最便宜可用来源计费。

### `server/tool_registry.py` — 工具能力
任务声明能力而非工具名，注册表解析。策略在声明之后应用，所以任务不能靠点工具名扩权。

**诚实的局限**：能力筛选对这套工具集基本没效果（`EVIDENCE`/`NEWS` 标签太宽），实际减工具靠的是调用数据。

### `server/prompts.py` — 模型提示词
从 `agent.py` 抽出，有测试。**这是防止它再次过时的机制**——提示词里曾有多处描述与代码不符。

### P2 — 设计意图，不是待办

**D-1：权限四层。** `docs/DESIGN_PRINCIPLES.md` 第六节。第 1-3 层（写数据、写呈现、改自身行为）应该放开，第 4 层（改规则：权限、白名单、访问范围）必须按住，理由是**可审计性**而非信任——能改写自己约束的系统等于没有约束。目前代码还没体现这个分层，因为还没有 AI 自主改行为的入口。

## 4. 硬约束（不要违反）

1. **只保留 `main`**，交付前打标签。不要改写已共享历史。
2. **不要动 `football-ai-harness-loop` 仓库**（另一个仓库）。
3. **跑测试**：改完必须 `python scripts/check.py --suite full`；界面改动加 `npm run test:ui` 和 `npm run build`。
4. **不要放宽引用硬门**。`verification.prepare_claims` 验证引用指向本轮真读过的原文片段。它不判断真伪（符合定位），但它是防幻觉引用的唯一防线。用户明确同意删语义门，从未同意删这个。
5. **未登记域名不得默认提级**。`source_tier` 对陌生域名回落"未分类来源"。这是放开核验后的信任基础。
6. **凭据只走服务端加密存储**，不回显、不进日志、不进 URL（URL 会进共享请求缓存，等于落盘）。有测试守着这条。
7. **`data/`、`output/`、`tmp/`、`.env` 不提交 Git。**

## 5. 常用命令与踩过的坑

```bash
python scripts/check.py --suite full      # 959 项，约 110 秒
python scripts/check.py --suite fast      # 314 项，约 40 秒
python scripts/check.py --module test_xxx
npm run test:ui
npm run build
```

**踩过的坑**：

- **测试会污染全局注册表。** provider 注册是 import 的副作用。用 `providers.snapshot()` / `restore()`，**不要用 `reset()`**——它会清空整个注册表，让后续所有测试看不到真实来源，失败点跑到很远的别处。
- **provider 测试会因 pacing 真实等待。** 用 `providers.unpaced()`。之前一个模块因为 6 秒间隔跑了 30 秒。
- **Windows 上测试用 `IsolatedAsyncioTestCase`**，不要手动 `new_event_loop()`——会和内部循环冲突。
- **`Store` 用临时目录**，`tearDown` 里 `close()` 否则 Windows 文件锁会报错。
