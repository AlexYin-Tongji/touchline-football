**本轮必须保留的边界：**

- **社区源不能提供阵容名单。** `lookup_all_players.php?id=<队>` 只返回约 10 条且含教练，小球队为 0。名单只能来自 ESPN，社区源只供事实与图像——「一个队一个源」在名单这层不成立，身份匹配不可省。
- **出生日期差一年的同名者必须继续拒绝**（全量 53 人）。Reece James、João Pedro、Víctor Muñoz（源记 1957）都不是「数据模糊」，是确定的不同人。任何模糊判断都会把陌生人的脸挂上去。
- **图像只认 cutout**：500×500 PNG、透明底、棚拍，同一主机路径。`strThumb` 是另一套风格且按 ID 拼会 404，不设 thumb 兜底——风格统一优先于覆盖率。
- **候选实体必须打分排序，不能取第一个通过的。** 切尔西的 `P31` 是 `Q103229495`；早期类别表漏列它，脚本跳过正确实体、选中「切尔西发展队与青训学院」(Q2669653)。两者都是「足球俱乐部」，类别表不完整会把正确答案静默变成错误答案。续跑时**必须重新校验已存实体**，不能信任自己上一轮的输出。
- **官网阵容页 ≠ 可用照片源。** 里尔把头像命名为 `Berke dos.png`、无 alt、无号码，按姓氏猜会挂错人的照片。两件事在 `server/squad_pages.json` 与 `tests/test_team_portraits.py` 中分开记录。
- **`PHOTO_SOURCE_ORDER` 是实测顺序，不是偏好。** 调整它必须重测覆盖率与成本；`photo_outranks` 是唯一裁决点，`_apply_photo` 内拒绝弱源覆盖。四个社区标签同排名（同源内可刷新自己）。
- **改匹配规则必须同时清缓存。** `missing`/`ambiguous` 是持久结论（存活 7 天），清了缓存不改规则没用，改了规则不清缓存则被误判的球员不会回来。
- **社区源记录含 `strEthnicity`、`strWage`、`strAgent`**，任何产品字段都不得读取。
- **昵称只接受拉丁字母**：维基声明保留录入语言，阿斯顿维拉原文为希腊语。
- 补全只写缺失字段，**不覆盖已审阅值**（阿森纳等四队保留手写中文资料）。

**下一轮候选：** 官网照片源的通用抽取（当前仅 3 队有手写配置）；62 队无昵称声明；用模型为无解球员提**候选拼写**（图片仍只从社区源取，且不得用于出生日期矛盾的 53 人）；`refresh_team_sources` 与 `research_news` 合并。

1. 以 [DESIGN_PRINCIPLES.md](DESIGN_PRINCIPLES.md) 为准：整合信息、展示来源，真伪交给读者。来源层级决定措辞，不决定资格。
2. 只保留 `main`，交付前留回退标签，不改写共享历史；不修改 `football-ai-harness-loop`。
3. `prepare_claims` 仍要求本轮真正读过且当前仍可见的片段；子任务、结构化查询和维护日志不授予引用资格。比赛截止线、固定文章范围与避剧透边界继续生效。

5. 自动测试只用临时库与本地替身；真实验收必须限量、区分测试材料。修改用户库前成对备份库和 key。
