# 看台 V8.5：球队资料补全与照片权威源

2026-10-08 交付。这一轮做四件事，全部围绕「一个字段一个权威源」。

## 1. 队徽路径统一（修缺陷）

四个队徽指向根目录（`/assets/arsenal.svg`、`/assets/liverpool.png`、`/assets/barcelona.png`、`/assets/inter.png`），其余 92 队指向 `/assets/clubs/`。根目录文件保留作旧 URL 兼容并登记在 `compatibility_assets`，目录本身改指 `clubs/` 下的同一份文件。`tests/test_club_library.py` 现在断言路径前缀、并要求 `clubs/` 下每个图片文件被引用或登记——此前有四个无人引用的文件。

## 2. 球队简介字段按一个权威源补齐

成立年 42/96 → **96/96**，主场 20/96 → **96/96**，昵称 4/96 → **34/96**。全部来自 Wikidata（CC0），逐队记录实体编号、来源页面与核验日期。阿森纳、利物浦、巴萨、国米四队保留本地手写中文资料，不被覆盖。

昵称只接受拉丁字母结果：维基数据的声明保留录入语言，阿斯顿维拉的昵称原文是希腊语，混在中英对照的资料表里不如留空。

工具：`scripts/enrich-clubs.py`（离线、可断点续跑、只写缺失字段）。

**这一步犯过一个必须记住的错误。** 切尔西本身的 `P31` 是 `Q103229495`（association football club），早期类别表漏列该类，脚本于是跳过正确实体、选中 `Q2669653`「切尔西发展队与青训学院」——两者都是「足球俱乐部」。类别表不完整会把正确答案静默变成错误答案。修正为：候选按具体性**打分排序**取最优（而非取第一个通过的），并在续跑时**重新校验所有已存结果**（批量 50 个一次，90 队只用 2 次请求）。重校验抓出 3 个错误实体（chelsea、osasuna、brest）。

## 3. 球员照片：一个球员一个权威源

四个源此前**最后写入者胜出**——`_apply_photo` 清空全部十个字段，被五处调用；社区照片可以覆盖 ESPN 已确认的结果，官网卡片可以把维基照片必需的许可字段抹掉。现在顺序是实测出来的，不是偏好：

| 源 | 覆盖 | 不可达 | 成本 |
| --- | --- | --- | --- |
| 官网目录 | 78/96 = 81% | 0 | < 2 秒/队 |
| TheSportsDB（社区） | 145/238 = 61% | 0 | 27 秒/队 |
| Wikimedia | 11/98 = 11% | 6 | 174 秒/队 |
| ESPN 名单头像 | 9/349 = 3% | — | 免费 |

`PHOTO_SOURCE_ORDER` / `photo_outranks` 统一裁决，`_apply_photo` 内拒绝弱源覆盖强源。采集顺序改为**社区先于维基**，维基只处理社区未解决的球员。

**顺带修掉两个真实缺陷：**
- `portrait_directory` 比较 `final_url.rstrip("/") != config["url"]`——只剥一侧尾斜杠，凡末尾带 `/` 的官网配置永久报「地址已变化」。尤文图斯因此 0/37，修复后 24/37。
- `_enrich_wikimedia_photos` 的 `if force and explicit_selection or row.get("photo_url") and ...`——`and` 比 `or` 紧，显式重试会被无关条件跳过。

**关于「球员信息与图像同一源」**：TheSportsDB 完整记录同时含事实与照片，`idESPN` 与名单 `provider_id` 在 48/48 例中吻合、零冲突，是真实的身份锚点。但链条是趋向而非定律：它认识的球员中 **73% 有照片**，缺口是第三门将与 2000 年后出生的替补。

**隐私边界：** TheSportsDB 记录还含 `strEthnicity`、`strWage`、`strAgent`，任何产品字段都不得读取。

## 4. 官网阵容页全目录发现

96 队中 **43 队**找到可验证的阵容页（验证方式：页面出现的球员全名数 ≥ 阵容的 1/4），记录在 `server/squad_pages.json`。27 队官网为客户端渲染、静态 HTML 无球员名，26 队只匹配到新闻页或统计页（已记录拒绝原因）。

**43 个页面不等于 43 个可用照片源。** 里尔把头像命名为 `Berke dos.png` 且无 alt、无号码——按姓氏猜会挂错人的照片。`usable_as_portrait_source.blocked_by_identity` 记录了这类情况，`tests/test_team_portraits.py` 断言「已验证页面」与「可用照片源」两件事不得混同。

## 5. 社区照片的身份匹配：从「姓名+国籍」到「姓名+出生日期」

2026-10-09 补做。第 3 步解决了「哪个源说话算」，这一步解决「同一源里哪条记录是这个人」。

对 96 队全部 2834 名阵容球员实测三级解析，产品原基线约 **1974/2834 = 70%**。原规则要求「全名精确一致 **且** 国籍一致 **且** 出生日期逐日一致」，三处都会误杀：

| 误杀类型 | 全量人数 | 实例 |
| --- | --- | --- |
| 拼写变体（源用另一种拼法） | 62 | `Branco Boomen` ← `Branco van den Boomen`；`Nazinho` ← `Flávio Nazinho` |
| 出生日期只同年不同日（源数据粗糙） | 46 | Ezri Konsa 10-23 vs 06-06；Bentancur 06-25 vs 06-05 |
| 双国籍（ESPN 与源的国籍声明不一致） | 2 | Belkhdim：ESPN 记摩洛哥、源记法国，出生日期同为 2002-02-14 |

新增四级匹配，**全部以出生日期为第二事实**，国籍从「拒绝条件」降为「辅助信号」：

| 标签 | 依据 |
| --- | --- |
| `community_name_and_nationality` | 全名 + 国籍（原规则，保留） |
| `community_name_and_birthdate` | 全名 + 出生日期逐日一致（可越过国籍不一致） |
| `community_name_and_birth_year` | 全名 + 仅年份一致（源的精度所限） |
| `community_surname_and_birthdate` | 姓一致 + 出生日期逐日一致（源用了另一种拼法） |

**必须继续拒绝的：出生日期差一年的同名者，全量 53 人。** Reece James（ESPN 1999-12-08 / 源 1993-11-07）、João Pedro（2001-09-26 / 1987-12-29）、Víctor Muñoz（2003-07-13 / **1957-03-15**）。这不是「数据模糊」，是确定的不同人；交给任何模糊判断都会把陌生人的脸挂上去。所有四个标签的排名相同（同属一个源，只有它自己可以刷新自己），`photo_outranks` 仍拒绝更弱的后备源覆盖它。

**实测效果**：Angers 真库端到端 **15/26**，其中 `community_name_and_birthdate` 13、新增的 `community_surname_and_birthdate` **2**——与离线测量脚本逐条吻合。全目录估算 70% → 约 73.5%（+约 106 张）。

**不可由匹配规则修复的部分（必须留空）：** `no_record` 438 人（源根本没有）、`tier1_no_image` 153 人（源有记录无图）——合计 20.9%，是源本身的覆盖缺口，正是二队与年轻替补。

**缓存已在改规则时清空。** `missing`/`ambiguous` 是持久结论（存活 7 天），不清则被误判的球员不会回来；清空前后对比：metadata 655 → 448 键（删除 `community_portrait_v%` 207 键），`settings`、`transient_bodies_v1` 等未受影响。清理前备份 `data/backups/before-v8.5-portrait-matching-20261009-142958.{sqlite3,key}`。

## 已知限制

- 官网照片源仍只有三个队有手写抽取配置。通用抽取未实现：多数官网阵容页的静态 HTML 不含可安全匹配的球员头像，强行抽取会违反「跨源匹配须有明确身份依据，缺图留空」。
- 昵称 34/96：其余 62 队的维基数据无昵称声明，或声明为其他文字。
- 社区源与维基源的真实可用性是有限时点观察（2026-10-08 / 10-09），不证明永久可用。
- **名单不能取自社区源**：`lookup_all_players.php?id=<队>` 只返回约 10 条且含教练（阿森纳首条是助理教练 `Albert Stuivenberg`），小球队为 0（Angers 被记为手球队）。阵容名单只能来自 ESPN，社区源只供事实与图像——所以「一个队一个源」在名单这一层不成立，匹配不可省。
- **图像只有 cutout 一种可用风格**：500×500 PNG、透明底、棚拍，同一主机路径。`strThumb` 是另一套风格且按 ID 拼接会 404，故不设 thumb 兜底——风格统一优先于覆盖率。
- 未做：用模型为无解球员提候选拼写。收益未测，且**不得用于出生日期矛盾的那 53 人**。
- `tmp/photo-exp/` 保存实验脚本与其 JSON 结果：`experiment.py`（各源覆盖）、`chain.py`（记录→照片链条与 `idESPN` 锚点）、`find-squad-pages.py`（全目录官网发现）、`tiers.py`（本步三级/四级身份解析，全量 96 队）、`verify-live.py`（真库端到端验证，走隔离副本）。
