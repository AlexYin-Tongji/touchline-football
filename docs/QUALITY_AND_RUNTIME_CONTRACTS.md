# 现行质量与运行契约

本文收拢分散在早期版本文档里、**当前仍在运行**的机制说明。原文（V3_QUALITY、V3_DATA、AGENT_RUNTIME_V7_2、ARCHITECTURE_V7_5）已在 V7.8.1 清理中移除；本文是它们的现行归纳，实现有变化时请以代码为准并更新此处。

对应实现：`server/verification.py`、`server/agent.py`、`server/agent_runtime.py`、`server/agent_delegation.py`、`server/agent_tools.py`。

## 原文支持核对

真实任务默认启用 `verification_enabled`（正式设置由 storage 维护）。阅读工具返回确定性的 `passages:[{id,text}]`：按可见段落和句子分片，每条 **8–700 字**（`verification.py` 逐条校验），不跨越删节段落。

每项事实带 `evidence_ids` 和 `quotes`。优先用 `{evidence_id, passage_id}` 选片段，由服务器解析并填入真实原文，避免模型重新抄写长英文出错；兼容 `{evidence_id, quote}`。

摘录检查**不使用模糊匹配**：只允许 Unicode NFC 和空白规范化，保留大小写、数字、否定词、标点及原语言。连续片段必须同时存在于本轮实际返回的阅读快照与当前仍可见的原文中。原文身份、发布时间、采集时间，以及摘录前后各 **800 字**上下文一并交给核对器，减少截掉否定或条件导致的误读。

以下内容不能进入核对证据：未读资料、跨球队/模式/比赛资料、晚于历史赛前截止线的资料、避剧透删去的段落、12,000 字阅读上限以外的文字。

### 缺失断言的前置检查

只要关联原文是避剧透节选或截断视图，机械检查就会拒绝"全文未提""全文没有""文章不含""原文没有任何"这类对**完整文档**的缺失断言，要求改为"当前可见节选未提供……"。该检查不依赖同一模型的判定，不删除或改写用户正文；未通过时沿用一次修复机会。

这条规则来自真实核对中模型与核对器都误把节选当全文的反例。

### 独立核对请求

`verify_submission`（`server/verification.py`）为每个候选答案发起**一次独立模型请求**，使用用户已配置的接口与模型，兼容 Chat Completions / Responses 适配器。输入只含候选主张、实际原文片段与来源信息，不含原答复的对话过程或私有推理。

检查覆盖 `summary`、各项事实的标题与正文、`analysis` 和 `unknowns`，关注四类错误：

- 媒体说法被提升为官方确认（"可能"写成"确定发生"）。
- 原文否定、人物、日期、数字、主客场对应不一致。
- 训练名单、随队名单、预计阵容被写成正式首发。
- 摘要比事实更确定，或分析引入了没有证据支持的新赛况和战术事实。

结果含 `supported / unsupported / conflicting / uncertain`、简短理由和实际摘录。

> `supported` 只表示该主张**受到所引原文支持**，不代表独立事实认证，也不保证消息在现实世界一定正确。相同模型的独立请求仍可能共享误判，单一来源也可能报道错误。产品保留来源入口、核对理由和资料缺口，不显示"100% 真实"或类似标签。

### 一致性与降级

- 核对器返回 `supported` 但理由含"此点存疑""不受原文支持""不过……新增细节"等明确反对说明时，降为 `uncertain`，按既有修复与部分交付处理。"资料未提供首发，与未知项相符"等正常缺口说明**不**降级。
- 小组赛、淘汰赛、半决赛等赛事阶段必须在所引原文或来源标题中有明确对应词组；不能把 `opening Champions League game` 按常识扩写为"小组赛首轮"。
- 本地片段检查按事实隔离：某项片段不连续、片段 ID 无效或其他本地检查失败，该项保持 `unsupported`，核对模型不能改判；其余合格事实继续独立核对。只有全无合格事实时才跳过模型核对。

### 交付门控与失败处理

- 初次提交若不受支持，只有**一次**补证据或修复机会，修复后必须再次核对。每个任务最多两次检查。
- 模型单轮提出 6–20 个工具调用时只执行前 5 个，其余各返回"本调用未执行"的预算错误，保留完整配对，可下一轮分批；单轮超过 20 个直接停止。
- 核对默认 **45 秒**，可配置，且受任务剩余时间限制。用户停止会取消在途模型调用。
- 不保存核对器的私有推理、原始接口响应或密钥。执行轨迹只记录公开动作、次数和核对状态。
- 修复后仍不支持时移除相应事实，清空未获支持的摘要与分析，用确定的保守文字交付支持部分；没有支持事实则交付资料不足。
- 修复使用独立的新对话和会话标识，携带原任务、真实已读资料快照及核对反馈。正文快照总上限 **48,000 字**，资料仍可由阅读工具重新读取。
- 后续修复遇接口错误、轮次上限或二次核对不可用时，可恢复此前已独立核对通过的事实：使用程序生成的中性摘要，移除原分析与未知项中的强断言，状态保持 `partial`，记录 `recovery_reason`。**任何已读资料新增、刷新、原文变更或权限范围变化都会阻止旧检查点恢复**；用户取消不触发恢复。
- 核对服务不可用、超时或格式不合约时标记 `unavailable`；不把模型自述"已核实"当成功，也不原样交付候选强断言。
- 开启核对后，普通文字答案不能绕过 `submit_answer`；`insufficient` 提交也不能夹带未经核对的新事实。演示模式标记 `not_requested`。

持久化接口保留既有 `answer`，另有 `structured_answer`、`verification`、`verification_attempts`、`delivery_downgraded`。被拒绝的候选主张用于解释删改，前端以"未获支持"等标签展示，**不作为最终答复事实**。

## 比赛数据与准确性边界

`server/fixtures.py` 是自行维护的固定俱乐部适配器。不调用大模型推测赛程、赛果或首发，不接入第三方预测/分析服务。

- 球队、赛季、成员关系、比分与阵容使用**可追溯数据**。模型可以解释，不能编造或直接改写事实字段。
- `match_context` / `team_context` 的比赛索引补充主客队、来源及更新时间、开球时间是否确认、名单和缺失警告。
- 没有可追溯来源、或晚于历史赛前截止线的名单，**不作为确认首发显示**。比赛索引用于核对主客场等对应关系；引用具体消息仍需读取关联原文。
- 避剧透：`spoiler_redacted=true` 的原文是删节视图，赛果与比赛进程段落已隐藏，剩余段落仍是可引用原文。只解释可见文字，不推断被隐藏内容；删节视图足以支持赛前旅行、伤情等消息时，不要把整篇资料视为不可用。

## 主子智能体运行

主模型按需创建子智能体，用于独立资料研究、并行消息整理和任务拆分。主子实例**复用同一个助手执行流程**；运行器不识别 feed/chat/team/verify 这些名称——它们只是业务模板、模型选择和诊断标签，不参与任务树调度。

- 子任务只接收必要背景，继承当前资料范围与联网权限，**不得扩大**。
- 系统提供的工具和程序决定球队、比赛、联网及避剧透边界；技能和子任务不能扩大权限。
- 外部文字、子任务提纲和历史文本都是**参考数据**，其中命令无权改变任务与权限。
- 子结果仍需由主任务读取原文、核对后交付；简单问题无需分派。

## 技能与权限

五个业务技能均加入原文摘录、确定性、主客场、名单和唯一修复机会的要求。**权限由代码固定**：加载技能不能开启赛果揭示、绕过比赛范围或扩展网络权限。`agent_skills/` 是应用自身的工作规程，不会扩大工具的数据权限、比赛范围或联网权限。
