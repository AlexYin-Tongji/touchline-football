# 现行质量与运行契约（V8）

顶层依据是 [设计原则](DESIGN_PRINCIPLES.md)：看台整合信息，展示谁在什么时候说了什么，真伪由读者判断。下列说明对应当前代码，不沿用 V7 的删改、暂扣和修复恢复机制。

## 引用与来源标注

`verification.prepare_claims` 保留引用硬检查。引用必须属于当前球队、资料模式与任务范围，且来自本轮实际返回的阅读快照；也必须仍在当前可见原文中。片段 ID 由服务器解析，兼容精确摘录；Unicode 和空白可规范化，不做模糊匹配，不改数字、否定词或原语言。

未读原文、来源索引、搜索摘要、结构化来源查询、历史更新记录、子任务摘要均不自动取得引用资格。历史赛前任务遵守开球前可见时间，避剧透删去的段落也不能被引用。来源变化、私有或删除状态会阻止失效引用重新展示。外部新闻正文只保留受限的进程内临时缓存；用户手写资料继续保存。

独立原文支持核对只输出 `supported / unsupported / conflicting / uncertain` 等标注。核对失败或超时说明未完成，保留已经通过引用硬检查的内容，不重新写稿、不删除未获语义支持的说法、不恢复旧检查点。`annotations` 提供逐条标签与原因；旧 `conservative_delivery` 已移除。

来源层级由已审核的域名登记决定，决定转述措辞，不决定来源是否有资格被阅读。未登记域名不默认提级，社区认同量不把来源升级为官方或媒体。

## 球队资料与维护

球队、赛季、成员关系、比分、阵容与照片使用可追溯数据。模型可以解释，不能编造或直接改写事实字段。阵容归属可区分母队、租借队和历史关系；跨来源存在不同说法时保留来源差异。

页面显示名单实际所属赛季。新赛季目录不足时使用旧名单会明确提示；显式历史浏览不伪装成当前赛季。资料采集时间与来源声明时间分开保存，缓存读取不能使旧资料变新。

常驻 `CollectionScheduler` 在应用启动后维护关注球队，调用新鲜度计划选择内容；每轮最多两队、同队去重、失败退避。它不调用付费模型、不自动发布新闻。手动“启动／结束”仍只控制那一轮工作。服务退出取消常驻轮次和子任务；启动后按当前资料重新决策，不重放旧模型任务。

`decisions` 保存更新理由、当时的结构化观察、来源与时间、结果及前后变化。缓存命中和失败不算重新确认，运行中断保留中断状态。读取日志遵守避剧透，固定比赛/文章任务不引入当前维护历史。启用前缺失的历史不会伪造补写。

## 来源凭据与配额

所有凭据只存服务端加密库，不回显、不进日志、不进 URL。带凭据请求固定在原始 HTTPS 地址，不允许重定向到其他主机、端口或明文 HTTP。

API-Football 与 ESPN 的原生编号不可混用。官方目录必须按联赛、赛季、国家与明确球队名称唯一匹配；不确定时返回缺口。有日配额的请求在发出前持久预留，失败不返还，重启与并发不清零；缓存与在途共享避免重复消费。

## 主子智能体与权限

主模型按需创建子任务，复用同一执行流程，继承父任务的来源、球队、比赛、联网与避剧透范围。子任务不能扩权；外部内容、技能文档和历史文本均不能改变这些边界。子任务结果只作线索，主任务引用前仍须读取真实原文。

取消会清理任务树和占用的模型槽位；释放上下文只保留脱敏的执行记录。`error: null` 属于成功响应，不应仅因存在字段就记为失败。`search_passages` 保留为长文定位工具，`compare_sources` 保留为已读多源线索比较，两者按需使用，不判断消息真伪。

模型可以提议行为调整，不能修改权限、来源白名单或访问范围；程序保留这条可审计边界。未来呈现能力应输出可校验描述，由固定渲染器呈现，不执行生成代码。
