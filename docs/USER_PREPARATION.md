# 你的足球 Agent：上线前要准备什么

适用于本轮 **2026/27 五大联赛与跟队报告版本**，说明核验日期：**2026-09-12**。

你现在主要准备三样东西：**一个 GitHub 私有仓库、一个能支付托管费用的 Render 账户，以及可从云端调用的模型服务**。代码、球队素材、数据库结构和部署配置由我们维护。当前方案不需要你另买一台服务器，也不需要先购买足球数据 API。

## 一、现在必须准备

### 1. GitHub 账户与私有仓库

如果还没有仓库，在自己的 GitHub 账户里新建一个 **Private（私有）** 仓库，名字可以叫 `football-agent`。新仓库保持为空即可，不必额外生成 README、许可证或模板文件，我们会把现有项目推送进去。如果已有合适的仓库，直接使用它，不要覆盖或删除已有内容。

准备好仓库的网页地址或 HTTPS remote URL，例如：

```text
https://github.com/你的用户名/football-agent
https://github.com/你的用户名/football-agent.git
```

这两种地址都可以发给我，里面不应包含密码或访问令牌。仓库地址只是连接位置；真正的访问权限需要通过你自己的 GitHub 登录、GitHub 应用授权或本机已有凭据完成。**不要把 GitHub 密码、Token 或 SSH 私钥贴进聊天。**

本次要部署的分支是 **`codex/five-leagues-reports`**。仓库中的旧 `main` 不代表这次完成的版本。远端准备好后，我们会核对现有 remote、推送本轮分支，并确认远端确实有新版代码；你不需要手工复制项目文件。

### 2. Render 账户、仓库授权和付款方式

注册或登录 [Render 控制台](https://dashboard.render.com/)，准备好可由 Render 接受的付款方式。个人项目可以先使用 **Hobby 工作区**，网站运行实例与磁盘会另外计费。

把 GitHub 连接到 Render。可在 Render 的 **Account Settings → Git Deployment Credentials → Add credential** 中选择 GitHub，完成授权，并让 Render 能访问本项目的私有仓库。页面出现仓库列表后，应能找到刚准备的那个仓库；找不到时先检查仓库授权范围。[Render 官方仓库连接说明](https://render.com/docs/git-provider)

本项目目前的起步费用按以下配置估算：

| 项目 | 当前配置 | 参考月费 |
| --- | --- | ---: |
| 工作区 | Hobby | 0 美元 |
| 网站运行实例 | Starter，现名 `0.5c-512mb`，0.5 CPU / 512 MB | 7 美元 |
| 持久磁盘 | 1 GB | 0.25 美元 |
| 基础托管合计 | 一个网站实例 + 一块磁盘 | **约 7.25 美元 / 月** |

这是按整月运行计算的基础估算，**不包含税费、可能产生的额外流量或构建费用、域名费用，以及模型调用费用**。最终以创建服务时的费用预览和账单为准。[Render 官方价格](https://render.com/pricing)

Render 在 2026 年 8 月更新了套餐名称；配置文件中的 `starter` 仍受支持，与 `0.5c-512mb` 的规格和价格一致。[官方套餐名称说明](https://render.com/docs/compute-plans)

**这里需要付费实例和持久磁盘。** 免费 Web Service 无法挂载持久磁盘，其本地文件会随重启、重新部署等操作丢失，不能承载当前以 SQLite 保存文章、偏好和模型设置的方案。把工作区升级成付费计划也不等于给网站实例配置了持久磁盘。[Render 免费实例限制](https://render.com/docs/free)

### 3. 模型服务的云端连接信息

新版网站会在 Render 的服务器上调用模型。开发电脑上已经保存的模型设置，**不会因为代码上线而自动出现在云端**。

你需要知道以下信息，之后直接填入网站的 **设置 → 助手连接**：

| 要准备的内容 | 怎么确认 | 是否可以发给我 |
| --- | --- | --- |
| 模型服务商 | 你实际使用的 API 服务商 | 可以 |
| 接口协议 | 服务商支持的协议，与当前设置保持一致 | 可以 |
| 服务地址 / Base URL | 服务商文档给出的地址；云端必须能访问 | 可以提供不含密钥或令牌的地址 |
| 模型名称 | 服务商提供的完整模型 ID | 可以 |
| API 密钥 | 在服务商控制台取得 | **不发聊天，直接填网站设置** |
| 余额或调用额度 | 服务商控制台确认可用 | 只需告诉我“已准备好” |

如果你现在使用的是 `localhost`、`127.0.0.1` 或家里局域网地址，Render 无法直接访问你电脑上的模型服务。此时先告诉我“目前用本地模型”，我们再接入一个云端可达的模型地址。把桌面软件订阅开通，也不应直接视为已经拥有可调用的 API；以实际服务商的 API 账户和额度为准。

模型生成报告、核对引用和回答追问会产生调用量。首次上线建议把“每轮最多整理”设为 **1 篇**，先确认报告质量，再按需要调整为 2 或 3 篇。服务商支持时，可在账户中设置消费上限和余额提醒，并确认其是硬性限制还是通知；应用里的整理篇数限制不等于精确的金额上限。

网站访问密码与模型 API 密钥是两回事：前者用于进入你的私人网站，后者用于调用模型。模型密钥由服务端加密保存；两者都无需交给聊天记录。

## 三、准备好账户后，按这个顺序部署

### 第一步：确认新版分支已在 GitHub

把仓库地址给我后，我们先完成 Git remote 核对和代码推送。你可以在 GitHub 网页的分支选择器里找到 **`codex/five-leagues-reports`**，并在该分支根目录看到 `render.yaml` 和 `Dockerfile`。

### 第二步：用 Blueprint 创建网站

在 Render 中选择 **New → Blueprint**，连接该仓库，按下表核对。Blueprint 会读取项目提供的配置，不必分别创建前端网站和后端服务。[Render Blueprint 创建步骤](https://render.com/docs/infrastructure-as-code)

| 页面项目 | 应选择或确认的值 |
| --- | --- |
| Repository | 你的足球 Agent 私有仓库 |
| Blueprint 分支 | **`codex/five-leagues-reports`** |
| Blueprint Path | `render.yaml` |
| Web Service 实际部署分支 | **同样是 `codex/five-leagues-reports`** |
| Runtime | Docker |
| 实例套餐 | Starter / `0.5c-512mb` 付费入门规格 |
| 实例数量 | 1 |
| 健康检查路径 | `/api/health` |
| 磁盘大小 | 1 GB |
| 磁盘挂载目录 | `/var/lib/touchline` |

**Blueprint 读取哪个分支，与 Web Service 最终运行哪个分支，都要核对。** Render 的服务 `branch` 未明确指定时可能使用仓库默认分支，不能只看 Blueprint 选中了新版就默认万事齐备。部署详情应显示本轮分支及对应提交，而不是旧 `main`。[Render Blueprint 的 branch 字段](https://render.com/docs/blueprint-spec#branch)

如果你希望指定服务器地区，在创建前告诉我，我们会同步到配置文件。地区会影响网络访问体验，Render 的服务地区创建后不能直接修改；没有特别要求时先采用项目配置。[Render region 字段](https://render.com/docs/blueprint-spec#region)

### 第三步：核对环境变量和磁盘

多数值由 Blueprint 设置，你只需确认它们存在。不要把本地 `.env` 文件整个上传到 GitHub，也不要把本机示例网址照搬到云端。

| 环境变量 | 云端应怎样设置 |
| --- | --- |
| `TOUCHLINE_SERVER_MODE` | `true`，启用私人网站访问保护 |
| `TOUCHLINE_ACCESS_PASSWORD` | Blueprint 自动生成；可自行改为至少 16 位的随机长密码，妥善保存 |
| `TOUCHLINE_DATA_DIR` | `/var/lib/touchline`，必须与持久磁盘挂载目录一致 |
| `TOUCHLINE_PUBLIC_URL` | 首次使用 Render 默认域名时通常无需填写，程序会自动识别；绑定自定义域名后填完整 HTTPS 根网址 |
| `PORT` | 使用 Render 提供的值，程序已按该值监听，不需要手工固定成 8765 |
| `FORWARDED_ALLOW_IPS` | Render 方案按项目配置设为 `*`，用于读取平台入口代理的信息 |

例如自定义网址为 `https://football.example.com` 时，`TOUCHLINE_PUBLIC_URL` 就填这个网址，不能填某个页面路径、查询参数或 `http://localhost:8765`。模型的服务地址、模型名称和 API 密钥在网站设置中填写，不要混入网站登录密码变量。

磁盘名称可以由配置管理，但**挂载目录必须是 `/var/lib/touchline`**。只有写入挂载目录的数据会跨重新部署保留；磁盘只由一个运行实例使用，附带磁盘的重新部署可能有短暂中断。[Render 持久磁盘说明](https://render.com/docs/disks)

### 第四步：核对费用后部署并登录

创建页面会列出将新增的服务和费用，核对后再点击 **Deploy Blueprint**。这是开始创建付费托管资源的实际步骤。

等待构建、启动和健康检查成功，复制 Render 提供的 `https://……onrender.com` 网址。打开网址后应先进入私人网站登录页面。

在 Render 服务的 **Environment** 中查看生成的 `TOUCHLINE_ACCESS_PASSWORD`，用它登录网站，并保存在自己的密码管理器里。如果你修改该密码并重新部署，旧登录会话会失效，需要重新登录。

### 第五步：连接模型，开始真实跟队

1. 进入网站 **设置 → 助手连接**，填写接口协议、服务地址、模型名称和 API 密钥。
2. 点击 **测试当前连接**，测试成功后点击 **保存连接**。
3. 将模式切换为 **真实跟队**；演示资料有明确虚构标识，不能作为实时新闻验收。
4. 打开 **五大联赛**，选择 **2026/27**，执行首次同步。球队目录可以先显示，赛程和积分要等同步完成。
5. 关注一支球队，采集消息，确认阅读室里有实际来源内容。
6. 在设置中开启 **收录资料后自动整理**，先设每轮最多 1 篇；进入 **跟队报告**查看整理进度和生成后的正文、来源及待确认事项。

模型连接成功不代表每个新闻网站都能读取。若某篇报告显示需要配置、来源不足或整理失败，打开具体原因，先修复相应问题；不要把“等待整理”当作已经产出的报告。

## 四、可后补：域名、旧数据迁移和备份

### 自定义域名可以以后再买

首次上线可以直接使用 Render 提供的 HTTPS 网址。以后想用自己的域名，只需准备已注册域名及其 DNS 管理权限，在 Render 添加域名，按控制台指引设置 DNS。证书由 Render 管理，待域名验证通过后，再把 `TOUCHLINE_PUBLIC_URL` 改为该 HTTPS 根网址，并统一通过这个网址访问。[Render 自定义域名说明](https://render.com/docs/custom-domains)

### 先决定云端从空资料开始，还是迁移本机资料

**从空资料开始**最直接：云端自动建立 96 队目录，你重新设置关注球队与模型，重新同步公开数据即可。开发电脑上的旧资料继续保留。

**需要保留本机文章、报告、偏好和历史**时，再做一次数据迁移。你先告诉我需要迁移，我们会安排一致性备份和传输，不需要你自行在服务器里覆盖数据库。

迁移时必须成套处理的默认文件是：

```text
本机：E:\football\data\touchline.sqlite3
本机：E:\football\data\touchline.key

云端：/var/lib/touchline/touchline.sqlite3
云端：/var/lib/touchline/touchline.key
```

如果你的本地运行目录曾改过，以实际数据目录为准。`.key` 是数据库内模型凭据的加密密钥，必须与同一份数据库匹配。只复制数据库、遗漏密钥，会使已经保存的模型密钥无法解密；云端访问密码则仍由 Render 环境变量单独控制。

完整迁移按以下顺序安排：

1. 暂停本机自动采集和 Agent 任务，建立一致性数据库备份，同时保存匹配的 `.key`。
2. 采用 SQLite 的备份机制，或在服务彻底停止写入后建立文件快照；如果停机快照中仍有对应的 `-wal` / `-shm` 文件，成套保留。不要在服务运行中只复制主数据库文件。
3. 先备份云端当前资料，再通过 Render 支持的安全文件传输方式传入备份。不要通过 GitHub 仓库、网页公开目录或聊天附件传输数据库与密钥。[Render 文件传输说明](https://render.com/docs/disks#transferring-files)
4. 在云端服务停止写入的维护窗口恢复，确认应用运行账户 UID 10001 对目录和文件有读写权限，再启动服务。备份传输可先完成，实际替换要在停止写入后执行。
5. 登录检查关注球队、旧文章、历史报告和模型“已配置”状态。确认可正常调用模型后，继续保留本机备份。

日常备份也应使用一致性数据库副本加配套 `.key`。持久磁盘负责跨重启保存数据，不能替代可恢复的独立备份。备份文件不要放到网站可公开访问的 `public/` 或 `dist/` 目录。
