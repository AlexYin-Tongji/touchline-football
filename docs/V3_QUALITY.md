# V3 原文支持核对

## 已实现的质量边界

真实任务默认启用 `verification_enabled`（正式设置由 storage 维护）。阅读工具返回确定性的 `passages:[{id,text}]`：按照可见段落和句子分片，每条 8–700 字，不跨越删节段落。每项事实带 `evidence_ids` 和 `quotes`；优先用 `{evidence_id,passage_id}` 选择片段，由服务器解析并保存真实原文，避免模型重新抄写长英文出错。兼容 `{evidence_id,quote}`。原文摘录检查不使用模糊匹配，只允许 Unicode NFC 和空白规范化；保留大小写、数字、否定词、标点及原语言，连续片段必须同时存在于本轮实际返回的阅读快照，以及当前仍可见的原文中。

未读资料、跨球队/模式/比赛资料、晚于历史赛前截止线的资料、避剧透删去的段落、12,000 字阅读上限以外的文字，均不能进入核对证据。原文身份、发布时间、采集时间与摘录前后各 800 字一并交给核对器，以减少截掉否定或条件导致的误读。

只要关联原文是避剧透节选或截断视图，机械前置检查就会拒绝“全文未提”“全文没有”“文章不含”“原文没有任何”等明确对完整文档的缺失断言，要求改为“当前可见节选未提供……”。它不依赖同一模型的判定，不删除或改写用户正文；未通过时沿用一次修复机会。该规则来自真实核对中模型与核对器都误把节选当全文的反例。

## 独立核对请求

`server/verification.py` 的 `verify_submission` 为每个候选答案发起一次独立模型请求，使用用户已配置的接口和模型，兼容现有 Chat Completions / Responses 适配器。输入只含候选主张、实际原文片段及来源信息，没有原答复的对话过程或私有推理。

检查覆盖 `summary`、各项事实的标题和正文、`analysis` 和 `unknowns`，关注：

- 媒体说法被提升成官方确认，可能发生被写成确定发生。
- 原文否定、人物、日期、数字、主客场对应不一致。
- 训练名单、随队名单、预计阵容被写成正式首发。
- 摘要比事实更确定，或分析引入了没有证据支持的新赛况和战术事实。

每条核对结果包含 `supported / unsupported / conflicting / uncertain`、简短理由和实际摘录。`supported` 只表示该主张受到所引原文支持，**不代表进行了独立事实认证，也不保证消息在现实世界一定正确**。相同模型独立请求仍可能共享误判；单一来源也可能报道错误。产品应保留来源入口、核对理由和资料缺口，不显示“100% 真实”或类似标签。

本地片段检查按事实隔离：一项片段不连续、片段 ID 无效或其他本地检查失败，该项保持 `unsupported`，核对模型不能改判；其余通过本地检查的事实继续独立核对。只有全无合格事实时才跳过模型核对。最终可以交付 `partial` 的受支持事实，不能因为另一项复制失误而丢掉全部可靠内容。

针对真实复验中的两类错误，还增加了明确的一致性检查：核对器返回 `supported` 但理由包含“此点存疑”“不受原文支持”或“不过……新增细节”等明确反对支持的说明时，降为 `uncertain`，按既有修复和部分交付处理；“资料未提供首发，与未知项相符”等正常缺口说明不会因此降级。小组赛、淘汰赛、半决赛等赛事阶段必须在所引原文或该来源标题中有明确对应词组，不能把 `opening Champions League game` 按常识扩写为“小组赛首轮”。

## 交付门控、成本和失败处理

- 初次提交若不受支持，只提供一次补证据或修复机会；修复后的答案必须再次经过核对。每个任务最多两次检查，普通研究轮次和全局时间预算照常限制。
- 模型单轮提出 6–20 个工具调用时只执行前 5 个，其余各自返回“本调用未执行”的预算错误，保留每个调用与结果的完整配对，模型可在下一轮分批。单轮超过 20 个调用仍直接停止，避免无界批量输入。
- 核对默认 45 秒，可配置，且受整个任务剩余时间限制。用户停止会取消在途模型调用。
- 不保存核对器的私有推理、原始接口响应或密钥。执行轨迹只记录公开动作、次数和核对状态。
- 修复后仍不支持时，程序移除相应事实，并清空未经支持的摘要和分析，使用确定的保守文字交付支持的部分；没有支持事实则交付资料不足。
- 修复使用独立的新对话和会话标识，携带原任务、真实已读资料快照及核对反馈，避免不同供应商对最终工具被拒后的历史续接差异。正文快照总上限 48,000 字；资料仍可由阅读工具再次读取。
- 后续修复遇接口错误、轮次上限或二次核对不可用时，可以恢复此前已经独立核对通过的事实。只使用程序生成的中性摘要，移除原分析和未知项中的强断言，核对状态保持 `partial`，并记录 `recovery_reason`。任何已读资料新增、刷新、原文变更或权限范围变化都会阻止旧检查点恢复；用户取消不会触发恢复。
- 核对服务不可用、超时或返回格式不合约时标记 `unavailable`，不把模型自述“已核实”当成功，也不原样交付候选强断言。
- 开启核对后，普通文字答案不能绕过 `submit_answer`；`insufficient` 提交也不能夹带未经核对的新事实，程序会替换成明确的资料缺口文字。
- 演示模式标记 `not_requested`，不发起模型核对。缺少新设置字段的旧测试 FakeStore 保持 V2 行为；正式应用默认开启。

持久化接口保留既有 `answer`，新增 `structured_answer`、`verification`、`verification_attempts` 和 `delivery_downgraded`。核对记录中被拒绝的候选主张用于解释删改；前端应以“未获支持”等标签展示，不能将其当作最终答复事实。

## 比赛工具和技能

`match_context` / `team_context` 的比赛索引补充主客队、来源及更新时间、开球时间是否确认、名单和缺失警告。没有可追溯来源或晚于历史赛前截止线的名单不作为确认首发显示。比赛索引用于核对主客场等对应关系；模型引用具体消息仍需读取关联原文。

五个本地技能均加入原文摘录、确定性、主客场、名单和唯一修复机会的要求。权限仍由代码固定，加载技能不能开启赛果揭示、绕过比赛范围或扩展网络权限。
