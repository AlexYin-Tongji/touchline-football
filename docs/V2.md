# 看台 V2：可以交付跟队任务的足球助理

## 本轮必须交付

1. Chat Completions / Responses 双协议，分级诊断，保留已有密钥与设置。配置保存状态明确，原型不再提供会被误认成真实配置的保存入口。
2. 自研联网研究：查找球队已知可信来源的相关文章、读取原文、保存证据。资料不足时模型可补查，不能编造搜索结果。支持静态 HTML/RSS 和具有明确后备策略的动态页面。
3. 事件持续跟进：用户建立伤情/转会/球队主题任务，定时收集变化、运行解读、保留时间线与结论版本，服务重启后可继续，暂停/恢复/立即检查可操作。
4. 赛前—首发变更—赛后核对：保留历史版本，赛后读取同场证据和实际赛前观察，不把其他比赛或事后信息混入。
5. 自研 Skill 路由与组合，任务历史、重试/继续、轮次与时间限制；以真实资料和真实模型验收，失败有明确可定位原因。
6. 全面重做布局和视觉：紧凑顶栏、清晰主导航、单一主要工作区。今日动态、比赛、跟进、问答四个主入口；资料管理与设置作为辅助。减少重复边框、说明、统计块及装饰标签；正文 16px，主操作明确，桌面与手机都可用。

## 视觉方向

现代体育编辑部：白色阅读底、近黑文字、深墨色比赛面板、克制的亮蓝强调色，清晰留白和层级；球队色仅用于小型标记。顶部导航替代粗重左侧栏，正文优先，执行轨迹和证据按需展开。首页先呈现最新值得关注的事实与一项主要行动，避免后台仪表盘式堆叠。

## 接口增量（旧接口保持兼容）

Settings.llm 增加 `protocol: 'chat_completions'|'responses'`（旧配置默认前者）、`send_temperature: boolean`（默认 false）、`max_output_tokens: number`（默认 3000）、`use_env_proxy: boolean`（默认 true）。保存不测试，测试不隐式保存，需展示当前配置是否已保存。

另有 `thinking_enabled:boolean=false`，用于 DeepSeek 可选深度思考；轮次 2–16、输出预算 256–16000、单请求超时 10–120 秒。模型服务密钥只保存在服务端加密配置，旧配置平滑保留。

POST `/api/settings/test` 可接收以上 llm 字段，返回 `{ok, protocol, tool_support, message, checks:[{stage:'connection'|'generation'|'tools',ok,message}], elapsed_ms}`。错误详情仅展示脱敏后的状态/代码/参数级原因，禁止返回密钥与原始响应体。

RunInput.skill 增加 `auto`，默认由路由确定 ask/team_brief/match_preview/match_review/event_watch；增加 `allow_network: boolean=true` 和 `tracking_id?:string`。Run 增加 `skills_used:string[]`、`protocol`、`parent_run_id?:string`。POST `/api/runs/{id}/resume` 创建延续运行，保留同队同模式作用域和已读证据；不能把模型密钥存入任何运行数据。

Tracking: `{id, mode:'live', team_id, title, query, event_id?:string, match_id?:string, enabled:boolean, interval_minutes:number, last_checked:string|null, next_check:string|null, last_run_id:string|null, status:'idle'|'running'|'changed'|'unchanged'|'failed'|'paused', last_error:string|null, summary:string, baseline_evidence_ids:string[], updates:[{at,run_id,evidence_ids,summary}], created_at}`。

- GET `/api/state` 增加 `tracking:Tracking[]`、`source_catalog`、`setup:{model_configured,live_evidence_count}`。
- POST `/api/tracking` ← `{team_id,title,query,interval_minutes:30..1440,event_id?,match_id?}`。
- PATCH `/api/tracking/{id}` ← `{enabled?,title?,query?,interval_minutes?}`。
- POST `/api/tracking/{id}/check` → Run（先联网收集，若无变化不重复模型推理；首次需要建立基线）。
- DELETE `/api/tracking/{id}` 删除任务配置，保留资料与历史运行。
- GET `/api/source-catalog?team_id=...` → `{sources:[{id,name,url,kind,description}]}`。
- POST `/api/research` ← `{team_id,query,limit?:1..8}` → `{candidates:[{id,team_id,url,title,source_name,published_at}],errors:string[]}`。
- POST `/api/research/read` ← `{team_id,candidate_id,event_id?,match_id?}` → 导入结果。
- POST `/api/teams/{id}/collect` ← `{query?,limit?:1..6}` → `{added,unchanged,evidence_ids,event_ids,candidates,errors}`；收集无需 LLM，返回真实结果。

## 模块边界

- Root：server/main.py、server/storage.py、新增server/tracking.py，API/调度/存储迁移，文档、整合与端到端验收。
- 模型 Agent：server/agent.py、server/agent_tools.py、可加server/provider.py，agent_skills/**、tests/test_agent*.py、tests/test_provider*.py。
- 数据 Agent：server/ingestion.py、新增server/research.py与server/events.py，tests/test_research.py、tests/test_events.py；不要改storage/main/agent。
- 前端 Agent：src/**、package*、前端配置，独立V2原型可放prototype/v2.html；不要编辑server。

### 数据模块函数约定

`research.source_catalog(store,team_id)->list[dict]`

`async research.discover_news(store,team_id,query='',limit=6)->{candidates,errors}`：候选落库 `candidates` collection，mode='live'，按队伍隔离。

`async research.read_candidate(store,team_id,candidate_id,event_id=None,match_id=None)->{evidence,event,duplicate}`：候选须已发现且同队；保存原文，关联比赛与事件时再次校验。

`async research.collect_team(store,team_id,query='',limit=4,event_id=None,match_id=None)->{added,unchanged,evidence_ids,event_ids,candidates,errors}`：直接读取已配置来源/内置公开来源，最多读取limit篇，不调用第三方搜索/分析API。

`events` 提供有证据依据的事件去重与阶段建议/变化记录，不将转载数量提升为可信度。网络材料、来源主张、模型分析保持明确区分。

### 模型调用工具增量

保留5个本地工具，增加 `discover_news`、`read_article`（参数 candidate_id）、`refresh_team_sources`（限制次数/篇数）、`use_skill`（只从本地白名单加载附加技能）。联网读工具异步执行，预算/取消与作用域同样生效，引用必须读取实际入库原文。

新增第10个工具 `submit_answer`：以受约束的摘要、事实、引用、分析和未知项提交最终结果。通过引用/格式校验后，由程序渲染一份简洁正文并结束任务，避免模型把执行说明和重复草稿交给用户。

## 实际实现中的可靠性补充

- 自动采集的新闻若夹带历史比分，按完整段落生成明确标注的安全节选；原标题含赛果或手动标记内容仍隐藏。API、模型工具、列表摘要与写入回执使用同一个安全视图，原始资料不改写。
- 跟进主题改变时建立新的会话与资料基线，不继承旧主题上下文，也不把新主题材料追加到旧事件。历史结果保留在运行记录。
- 同一原文的不同抓取版本保持可审阅，但不按多个独立来源统计。
- 来源发现只检索公开索引标题/摘要；没有匹配不代表互联网上不存在该消息。可调整查询或配置自己的来源。

### 验收原则

不改动用户配置来伪装模型已连通。模型未配置时先给可操作配置入口，真实资料采集仍可使用。真实模型未成功完成最终任务前，不把协议模拟器测试称为真实模型验收。当前本机库尚未发现用户所述已配置的模型，正在确认配置页面。
