# V3 界面与球队图表

## 布局

今日页仅有三个内容区：最多三个重要变化、真实下一场比赛、最多三条有原因和依据的推荐。回答正文、原文、执行记录留在详情或问答中。保留今日 / 比赛 / 跟进 / 问答四个主导航，资料与设置为次级入口。

历史 V2 简报可以作为短卡继续阅读，但明确标记「未做 V3 核对」。新结论的支持程度来自服务端逐项核对结果，界面不把引用编号存在当成事实认证。资料不足时明确空态，不以英文原文截断拼成中文结论。

## 图表定义与口径

- 使用场景：比赛中心的球队近期表现，可随当前球队切换。首页不堆放统计仪表盘。
- 问题：这支球队最近已收录的完场比赛，结果与进失球分别如何？展示仅描述结果，不据此推断战术原因。
- 图形：逐场成组柱形，统一从零开始的球数轴；蓝实心为进球，浅色描边为失球，数字直接标注。胜 / 平 / 负文字标签避免仅用颜色区分结果。
- 数据：当前模式、当前球队，status=finished，比分和开球日期明确。优先使用 goals_for/goals_against；兼容旧数据的 score（当前球队–对手）。可选近 5 或近 10 场，先按日期取最近的完场比赛，再仅绘制比分明确的场次。缺比分场次明确提示，不用更早记录补齐。按开球时间升序展示。
- 范围：显示实际日期和实际场数；不足所选场数时明确提示，不填虚构数据。单场数据用柱形比较，不绘制不足样本的趋势线。
- 出处：逐场数据表保留来源链接；人工录入无链接时明确标记；demo 种子标记为虚构示例。
- 避剧透：开启后隐藏整个结果与进失球区域，包含汇总数字、柱形和数据表，提供前往设置的操作。
- 画布：React 产品中的原生 HTML/CSS 柱形；手机宽度不足时仅图表内部横向滚动。无需外部图表/足球数据 API。

## 交互

推荐的「阅读」打开资料/事件，「赛前/赛后」打开相应比赛页签，「跟进」预填任务，「核实」预填问答，「忽略」保存到服务端。展示推荐无需模型调用。自动更新默认关闭，自动生成解读也默认关闭；开启生成解读时明确提示会使用已配置模型。

设置保留 Chat Completions / Responses 的选择、模型密钥与连接测试。新增自动更新周期、同步比赛、自动解读、原文核对、立即运行，以及创建桌面入口和默认关闭的登录自启。
