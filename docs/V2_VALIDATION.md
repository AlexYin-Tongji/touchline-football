# 看台 V2 验证记录

日期：2026-09-09。源代码、已保存模型配置及数据库均在本机。V1 源码和数据的开发前快照保存在已被 Git 忽略的本机 data/backups/。

## 已完成的功能验收

- 重做顶栏、今日/比赛/跟进/问答四主入口，资料与设置为辅助入口。桌面 1440px 与手机 390px 实际浏览器检查通过，正文 16px、无横向溢出。
- 撤掉静态原型的模型输入和假保存按钮。原型持续标注仅用于设计演示，并提供正式应用入口。
- Chat Completions 和 Responses 两套真实协议实现；基础地址与完整端点校验；不自动切换协议。Responses 通过本地 HTTP 协议端到端工具循环验证。
- 使用用户提供的 OpenCode Go / deepseek-v4-flash 实际调用：连接、文本生成、工具函数/参数及工具结果续答全部通过。三层检查约 23 秒。密钥加密保存，网页回读不包含密钥。
- 四队公开来源实测可访问；阿森纳官方动态列表通过官网 sitemap 发现原文；阿森纳、利物浦发现约 7 秒。新闻正文、原始发布时间和来源链接均可取得，不使用第三方足球或搜索分析 API。
- 真实 UI 候选发现、读取、原文详情、模型保存/测试、跟进创建/暂停/删除、比赛历史、引用打开与关闭通过。验收跟进任务已删除，不留下后台循环调用。
- API、工具和页面使用同一避剧透节选函数。正文夹带历史赛果时可保留无赛果段落；原始文本不变。手动标记及赛果标题仍隐藏，写入回执也不泄漏原文。
- 跟进检查有新资料时解读，无新资料时跳过模型；改变主题时重建基线与会话，避免旧事件污染。
- 真实模型跟进任务已做两次连续检查：首次约 31 秒完成官网原文收集与带引用解读；第二次识别同一批原文没有变化，明确标注“本次未调用模型”。该测试在独立数据目录完成，任务已删除。
- 10 个自研工具、5 份本地技能。自动路由、技能组合、预算、取消、继续任务和实际已读引用约束均有测试。
- 结构化 submit_answer 终结工具统一生成一份结果，抑制过程性前言、重复草稿和过强的摘要认证标签；明确的条数上限会校验。

## 自动验证

全套 `python -X utf8 -m unittest discover -s tests` 共 **105 项通过**（14.548 秒），包括双协议 HTTP 端到端、工具预算/取消、引用提交、来源解析、事件归并、跟进周期、主题切换、密钥与模式隔离、避剧透安全视图及写入回执。

浏览器页面无控制台错误；TypeScript 与生产构建通过。源码、文档、原型和测试中已检查没有包含用户真实密钥的明文。

## 真实模型研究的质量迭代

第一轮真实研究暴露了“整篇避剧透过滤导致无资料”；第二轮可引用但有模型过程性口吻和重复；随后增加安全节选和结构化交付协议。正式 API 已完成官网与媒体原文的联网研究并给出引用（约 66 秒）。收紧条数与摘要后，最终正式调用 **33.4 秒完成**，按“最多两条”生成两项事实，引用 **3 篇原文（阿森纳官网 2 篇、卫报 1 篇）**，以程序统一格式交付，没有重复草稿或过程性前言。最新结果见 `output/v2-final-api-result.json`。

不把固定模型回复或协议模拟器输出当作真实模型效果。已完成的联网研究使用真实公开资料和用户配置模型，所有引用可打开原文或标注后的安全节选。

## 可用范围与限制

- 当前定位为本机单用户产品，正式地址 http://127.0.0.1:8765/；服务运行时才采集和检查跟进任务，未测试跨天连续运行，不提供关机后的云任务。
- 实际付费服务测试走 Chat Completions。Responses 已实现并通过完整模拟 HTTP 往返，尚未使用独立真实 Responses 服务账户进行长期验证。
- 公开索引检索依赖标题、摘要和少量足球词义映射，不代表覆盖全网。没有匹配时返回空，不用其他球员或无关文章补数。
- 资料是否构成实质新进展、每句话是否受原文充分支持，仍需真实样本和人工抽查。结构化与引用检查不能保证全部足球推断正确。
- 避剧透为保守文本规则，可能多隐藏段落，也无法保证识别所有隐含表达；不会用模型猜测被隐藏的部分。
