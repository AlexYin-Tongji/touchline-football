# V7.1：可靠采集、多模型协作与更清晰的界面

日期：2026-09-22。优化前主线保存在远端标签 `v7.0.0`（`d2f63e0`）。本轮继续只维护 `main`。

## 本轮解决什么

**动态采集**：文章读取改为有界并发，同一在途请求共享结果，失败来源短暂冷却；主动刷新可重试。成功资料及时入库，单篇失败不会使其他成功资料丢失。HTML结构化新闻先选主文章对象，标题、正文、时间保持一致。

**球队资料**：阵容、单队赛程和积分独立更新、分别保存；失败保留旧快照，只补缺失或过期部分。照片不再阻塞核心资料。页面显示各部分更新时间、错误和赛程覆盖范围，工具与维护skill使用同一状态。当前出口访问ESPN API会收到403，因此加入固定公开网页的备用读取路径，仍验证球队编号、赛季、球员身份、比赛状态与数值；不把占位零值当真实比分。

**项目运行时多模型协作**：协调层按独立新闻事件分发任务，最多两条报告并行；动态、对话、球队解读、原文核验可以配置不同模型。全局模型请求最多3个，同一服务地址最多2个。排队不消耗单次执行时限，取消会清理子任务；连续或交替重复结果且无进展时停止。核验模型在任务开始时固定，后续改配置影响新任务；修复核验配置可恢复耗尽重试的自动任务。未单独设置核验模型时跟随当前任务模型，但保持独立核验上下文。详见 [运行协调说明](HARNESS.md)。

**字体与界面**：采用用户选定的清爽浅色、绿色点缀，中文系统无衬线字体、16px正文和输入框、至少14px重要说明。配置区分功能分工和服务商；增加核验模型分工。修复草稿丢失、切队旧请求覆盖、新旧会话模型恢复提示和分类分页问题。

**运行与维护**：首屏使用轻量状态接口，非首屏页面按需加载；保留仅可见页面的低频轻量刷新，避免赛程过期。移除14个确认无引用的旧页面/样式文件，共享函数保留。SQLite种子写入批量提交，嵌套事务失败可回滚；旧库迁移和新增来源证明前自动备份数据库及密钥。更新检查依据内容指纹，依赖和素材变化会触发正确安装/构建，旧进程不会被误认作新后端。

## 测试方式

日常运行 `python scripts/check.py --suite fast`；局部修改使用 `--module test_模块名`；交付执行 `--suite full`、`npm run test:ui` 和生产构建。统一入口输出慢测试及耗时。共享测试初始化已提取，保留有价值的权限、来源、取消和升级回归；新增用例集中覆盖此次实际缺陷，没有为纯样式重复编写测试。

前端6项行为回归覆盖异步草稿、切队、分类、旧模型恢复和后台比赛更新。1440×1000与390×844实际浏览器验收无横向溢出，控制台无错误；中文字体实测为Microsoft YaHei UI。截图使用隔离合成资料，不代表用户的真实模型配置。

本轮本地完整回归 **506项全部通过，58.979秒**；快速套件测得173项约10.69秒，局部修改可进一步只跑对应模块。前端6项行为回归与最终生产构建通过，依赖一致性和差异格式检查通过。此前同机优化前完整回归为442项／108.336秒；两次范围和运行负载不同，只作为实际记录，不保证固定提速倍数。

完整回归、构建和真实来源检查记录保存在本机 `output/review/`；该目录不提交。远端交付结果另以主线CI及本次交付说明为准。测试不使用个人密钥调用付费模型，尚未宣称所有真实模型服务商都已联调通过。

## 使用与回退

双击项目内 `启动看台.cmd`。已有旧服务运行时，安装器会提示先停止再更新，避免新页面连接旧后端。若只是同一版本再次打开，会复用当前服务。

标签只保存代码，不包含个人数据库。迁移备份位于Git忽略的 `data/backups/`，数据库和同名 `.key` 应作为一组保留。回退前先备份当前数据，再恢复匹配版本，避免用旧代码直接打开不兼容的新数据库。
