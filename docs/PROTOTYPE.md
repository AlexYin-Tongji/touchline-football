# 看台 Touchline · 原型与交互规格

版本：MVP 1.0 · 2026-09-09  
对应需求：[PRD.md](./PRD.md)

## 1. 视觉方向

“球场边的一张清晰看板”：深绿、荧光黄与温暖浅底，结合球场线条和简洁的记分牌数字。主角是球队变化、比赛和证据。避免铺满统计卡片的后台界面。

| 元素 | 规格 |
| --- | --- |
| 品牌 | 看台 / TOUCHLINE；中文优先，英文作为轻量品牌辅助 |
| 深绿 | `#102D25`，用于导航、关键比赛区和主要文字 |
| 强调色 | `#D9F66F`，用于主要行动、活动状态和球场重点 |
| 页面底色 | `#F3F4EF`，正文卡片 `#FFFFFF` |
| 文字 | 主文字 `#18352C`；次文字 `#66766E`；边界 `#DFE5DC` |
| 状态色 | 信息蓝灰；错误暗红；示例与待确认使用清晰文字标签，不只靠颜色 |
| 字体 | 系统中文无衬线字体；比分、时间和序号可使用等宽数字 |
| 空间 | 桌面内容边距约 28–40 px；移动约 16 px；圆角 14–20 px；弱阴影或细边线 |
| 阅读 | 正文约 15–16 px、行距 1.6–1.8；重要标题较大；按钮至少 40 px 高 |
| 图形 | 简单球场网格、赛事分隔线、队名字母徽章；不依赖第三方照片或真实俱乐部商标 |

界面始终保留数据模式提示。演示示例的标识不能只存在于首次弹窗；真实模式的空白也不能偷偷填入示例内容。

## 2. 信息架构

```text
看台 Touchline
├─ 球队动态
│  ├─ 最近变化：全部 / 未读 / 关注
│  ├─ 消息详情与来源证据
│  └─ 下一场比赛快捷入口
├─ 比赛中心
│  ├─ 比赛信息与资料状态
│  ├─ 赛前观察
│  └─ 赛后复盘（避剧透控制）
├─ 跟队问答
│  ├─ 问题输入与上下文问题
│  ├─ 回答与证据
│  └─ 可展开执行步骤
├─ 资料来源
│  ├─ 已配置来源与采集状态
│  ├─ 添加 RSS / HTML
│  └─ 手动导入正文
└─ 设置
   ├─ 球队、解释深度、避剧透
   ├─ 模型连接
   └─ Agent 与采集运行参数
```

侧栏约 220–240 px，主区宽度随屏幕变化；较窄桌面可压缩为单栏。当前页名称、模式和球队在壳层中保持一致。模型未配置只在需要模型时提示，不能影响资料阅读。

## 3. 球队动态原型

```text
球队动态                            [我的球队] [虚构示例]
今天，跟上你的球队。
了解值得知道的变化，带着问题看下一场。

┌─ 深绿球队区 ─────────────────┬───────────────────────────┐
│  队名字母徽章  当前关注球队  │ 下一场                    │
│  当前资料模式与资料状态     │ 球队 A  vs  球队 B        │
│  [去比赛中心 →]             │ 时间 · 赛事 · 资料来源    │
└─────────────────────────────┴───────────────────────────┘

最近变化                   [全部] [未读] [关注]
┌─────────────────────────────────────────────────────────┐
│ 事件标签 · 未读       消息标题                           │
│                      一至两段来源摘要                   │
│                      来源标题 · 发布时间 / 未知         │
│                      [查看证据] [关注事件] [标记已读]    │
└─────────────────────────────────────────────────────────┘
```

卡片有明显标题和证据入口。重要性作为辅助标签，不让数字评分主导阅读。一次没有新内容时仍可进入全部资料。

交互：

- “未读”筛选在标记后立即更新，保存失败恢复原状态并给可读提示。
- “关注事件”切换为“已关注”，再次操作取消；关注筛选中无内容时引导关注一条消息。
- 点击证据打开详情：完整标题、原文、发布时间、采集时间、原始 URL；无 URL 时显示手动资料。
- “问问这条消息”带入该条资料的上下文并导航到问答页，不直接运行未经用户触发的昂贵任务。

空状态：**“还没有球队资料”**；辅助文案“添加一个你信任的来源，或粘贴一条消息开始跟队。”；主按钮“导入资料”，次按钮“添加来源”。

## 4. 比赛中心原型

```text
比赛中心                                  [虚构示例]
带着看点看球，再用事实复盘。

┌─ 深绿记分牌 ───────────────────────────────────────────┐
│ 赛事 · 比赛状态                                        │
│           球队 A          VS          球队 B           │
│                   开赛时间 / 尚未提供                  │
│ 资料来源与完整度                                       │
└────────────────────────────────────────────────────────┘

[赛前观察] [赛后复盘]
┌────────────────────────────────────────────────────────┐
│ 本场值得关注什么                     [生成/更新解读]   │
│ 01 观察点                                              │
│    为什么值得看；看球时可以留意什么                     │
│    [证据 1] [证据 2]                                   │
│ 02 观察点                                              │
│    ……                                                  │
│ 资料缺口                                               │
└────────────────────────────────────────────────────────┘
```

赛前观察和复盘共用证据详情。生成期间按钮进入忙碌状态，允许停止；失败后保留已有资料和上一次有效结果。

避剧透状态：记分牌保留对阵与开赛时间，用“赛果已隐藏”替代比分；赛后区仅显示保护说明与“揭示赛果并查看复盘”。揭示是该场明确的用户操作。未揭示时不得在摘要、推荐问题或来源标题中泄露赛果。

真实模式无比赛数据时不展示假对阵：**“下一场，等你补充资料”**，提供“导入比赛资料”；若有比赛信息但没有足够分析证据，展示“已有比赛信息，分析资料仍不足”。

## 5. 跟队问答原型

```text
跟队问答                    当前球队 · 当前资料模式
把问题问清楚，把依据留下来。

┌────────────────────────────────────────────────────────┐
│ 例如：这条伤病消息确认到哪一步了？                      │
│                                                        │
│ [有什么值得关注？] [下一场看什么？]      [发送问题 →]   │
└────────────────────────────────────────────────────────┘

┌─ 回答区 ───────────────────────────────────────────────┐
│ 状态：正在查阅本地资料                         [停止]   │
│                                                        │
│ 回答正文…… [1]                                         │
│ 事实 / 解释 / 仍待确认                                  │
│                                                        │
│ 来源证据                                               │
│ [1] 标题 · 发布时间 · [阅读原文]                       │
│                                                        │
│ ▸ 查看执行步骤（技能与工具记录）                        │
└────────────────────────────────────────────────────────┘
```

执行步骤展开后，每项只展示名称、状态、简短结果和耗时等可观察信息，例如“检索本地资料 · 找到 3 条”“阅读证据 · 完成”。不展示链式思维。回答支持安全的文本/Markdown 呈现，不渲染来源中的脚本或未经清理的 HTML。

| 状态 | 界面反应 |
| --- | --- |
| 尚未发问 | 提供上下文问题；不显示假的对话历史 |
| 没有资料 | 告知当前模式资料不足，提供导入入口 |
| 未配置模型 | 展示“先连接你的模型”，可保留问题并前往设置 |
| 运行中 | 阶段提示、停止按钮、防重复提交；已有证据保持可读 |
| 已完成 | 回答、引用与步骤完整显示 |
| 已取消 | 明确“已停止”；保留本次已取得的可用步骤，不当作完整回答 |
| 超时/轮次上限 | 展示停止原因和已有内容，提供重试及设置入口 |
| 模型错误 | 展示认证、网络、协议或服务错误的可读说明；不回显密钥 |
| 无效引用 | 移除无效证据链接并提示证据缺口；不能静默当作正确引用 |

在页面切换或切换模式时，运行任务必须维持明确状态。模式切换后不得继续把上个模式的结果展示在当前回答区。

## 6. 资料来源原型

```text
资料来源                              [+ 添加来源]
只跟进你信任的消息。

┌─ 手动导入 ─────────────────────────────────────────────┐
│ 标题                         原文 URL（可选）          │
│ 发布时间（可选）             主题 / 事件（可选）       │
│ 正文                                                   │
│ ▸ 比赛信息（可选）                        [导入资料]   │
└────────────────────────────────────────────────────────┘

已配置来源
┌────────────────────────────────────────────────────────┐
│ 来源名   RSS / HTML          已启用          [开关]    │
│ URL                                                    │
│ 上次成功时间 · 新增条数       [立即采集] [删除]         │
└────────────────────────────────────────────────────────┘

服务运行期间自动采集 · 采集间隔 · [调整设置]
```

添加来源使用轻量表单：名称、RSS/HTML 类型、URL、是否启用。保存错误贴近对应字段。一次性 HTML 文章同样保留为来源，用户可停用持续采集。

手动资料没有发布时间时允许保存，显示未知；不能默认伪造为今天发表。可选比赛字段包括对阵、时间、状态和比分，标签与证据关联明确。只有真正来自用户资料的内容可以进入真实数据模式。

来源失败展示其失败原因和重试入口，不影响资料列表可用。删除来源仅删除订阅配置，已经导入的证据默认保留；如需要删除资料，必须是独立且明确的操作。

## 7. 设置原型

```text
设置
把看台调整成你的跟队习惯。

┌─ 我的球队 ─────────────────────────────────────────────┐
│ 关注球队 [________________]                            │
│ 解释深度 [简洁 / 详细]          避剧透 [开关]           │
└────────────────────────────────────────────────────────┘

┌─ 模型连接 ─────────────────────────────────────────────┐
│ OpenAI compatible                                      │
│ 服务地址 [_______________________________________]     │
│ 模型名称 [_______________________________________]     │
│ API 密钥 [输入新密钥以替换_______________________]     │
│ 密钥状态：已配置 / 未配置                 [清除密钥]   │
│ [保存配置]  [测试连接]     最近测试状态与时间           │
└────────────────────────────────────────────────────────┘

┌─ 运行设置 ─────────────────────────────────────────────┐
│ 最大轮次 [  ]  请求/任务超时 [  ]                       │
│ 自动采集 [开关]  间隔 [  ]                             │
│ 仅在本地服务运行期间采集已启用来源。                    │
│ ▸ 当前工具与技能（只读）                               │
│                                         [保存设置]     │
└────────────────────────────────────────────────────────┘
```

配置密钥输入框不回填真实密钥；占位文案说明留空保留已保存密钥。“已保存”和“连接成功”分别展示，不能相互替代。测试按钮使用保存后的配置；有未保存修改时明确提醒先保存。测试运行禁用重复测试，完成后显示结果。

错误提示优先可操作：例如“模型服务拒绝认证，请检查密钥”“服务地址无法连接”“响应不符合兼容接口格式”。详细错误可折叠，日志中去掉密钥和认证头。

## 8. 演示与真实资料体验

| 环节 | 演示资料 | 真实资料 |
| --- | --- | --- |
| 顶层标记 | 黄色“虚构示例”及简短解释 | “真实资料” |
| 资料来源 | “演示资料，非真实新闻”；虚构人物/队伍/事件 | 手动导入或真实 URL 与原文 |
| AI 可用性 | 可以有明确标注的预置示例结果；实时运行须区分模型回答 | 必须由当前配置模型与真实资料支持；不能自动用示例替代 |
| 空状态 | 首次有可体验的内容 | 首次无内容；引导资料导入与模型配置 |
| 引用 | 只指向虚构示例原文 | 只指向真实模式中实际保存的原文 |

切换模式即时刷新页面上下文，已在运行的任务须取消或隔离展示，避免跨模式残留。

## 9. 原型交互验收

- 五个页面在桌面与窄屏可到达，焦点顺序合理，按钮和输入带可理解标签。
- 至少完整走通“动态 → 证据 → 问答”“比赛 → 观察 → 复盘”“来源 → 导入 → 新资料”“设置 → 保存 → 测试”四条路径。
- 在同一页面可辨识等待、空数据、加载、完成、失败与取消状态。
- 真实空数据和演示样例分别视觉检查；假数据不伪装成实时足球信息。
- 点击证据能真正阅读原文；模型状态和来源状态不能只是静态装饰。
- 窄屏内容不横向溢出；输入与操作按钮不被导航遮挡；深绿与荧光黄文字对比清楚。
- 交付时保留可运行页面作为交互原型，文档说明页面和状态，截图用于视觉复核。
