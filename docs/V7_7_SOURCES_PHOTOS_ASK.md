# V7.7 来源平权、球员照片与问答

这一版解决三个具体问题：动态来源有主次之分、球员照片覆盖率低、问答答复僵硬且慢。

## 动态：来源不再有主次

改动前，来源列表对读取顺序和结果取舍都有偏好，卫报还享有一套专属的冷却与降级逻辑，实际结果是它排在最后、失败后更容易被跳过。

现在：

- 所有已核验来源**同等对待**。排序只按来源 ID，保证稳定；`access_review_active` 和失败冷却不再改变顺序，冷却仍然照常限制请求本身，只影响"发不发"，不影响"排第几"。
- 候选排序改为**按内容相关性**：新鲜度、问题相关度、时间，最后才是 URL。官网不再获得额外权重。
- 每轮改为**轮转选取**：先让每个来源都进入列表，再给第二个名额。官网站点地图一次能提供几十条，此前会占满候选（阿森纳 39/40），把刚加的媒体订阅挤到只剩一条。
- **卫报订阅已整体移除**（catalog 中 96 条 `guardian_*` 条目），随之删除 `_guardian_host_health_key` 等专属分支。主机级冷却改为通用的 `SHARED_FEED_HOSTS` 判定，BBC 的球队订阅与全足球订阅共享同一主机健康记录。
- 新增经实测可用的媒体源：ESPN 足球（`espn_soccer`）与马卡报（`marca_football`）。L'Équipe 的订阅地址返回 403，未纳入。

## 球队：球员照片

此前球员照片主要来自 Wikimedia 的自由许可图片，覆盖率很低——阿森纳 27 人只有 6 张，利物浦、拜仁、维拉是 0 张。原因有两个：

1. **失败被当成定论。** `resolve_portrait` 把分类不出的异常一律记为 `rejected`，而 `cached_portrait` 对 `rejected` 采用 24 小时长缓存。于是一次网络抖动就成了"这名球员没有照片"，整队被冻结。
2. **没有可用的补充来源。** ESPN 球员页对脚本返回 202 空响应，这条路已经不通；官网目录此前只配置了巴萨一家。

现在的层级：

| 层级 | 来源 | 依据 |
| --- | --- | --- |
| 首选 | Wikimedia | 自由许可 + 俱乐部身份核验 |
| 补充 | 俱乐部官网目录 | 全名 + 球衣号码 |
| 补充 | TheSportsDB（社区库） | 全名 + 国籍 |

要点：

- **失败分类重写。** 只有身份歧义和许可判定才作为定论长期缓存；限流、超时、结构变化等都记为短周期的 `unavailable`，自动重试。
- **官网目录通用化。** `DIRECTORIES` 支持 `cards`（俱乐部自有类名，如巴萨）与 `entries`（任意球员项，如尤文）两种结构，新增尤文图斯（28 人）。解析仍要求全名与号码同时命中，号码不符宁可留空。
- **社区源交叉核验。** 社区库的球队字段不可靠（实测把维拉球员标成阿森纳），因此**俱乐部归属不参与判定**；只有当完整姓名唯一、国籍与阵容一致时才采用照片，并保留署名与"未声明开放许可"的说明。缺国籍时直接不查。
- 阵容解析不再写入 ESPN 头像（该路径返回空响应），照片一律由上述已验证来源填充。ESPN 球员页解析代码整体移除。
- 实测覆盖：阿森纳 8/10、利物浦 10/10、维拉 24/29。

## 问答：答复写成一段话

问答此前复用了新闻稿的提交结构：导语、条目化的事实、影响、待确认四栏齐备，还要先填引用片段再作答。这正是答复僵硬、且慢的来源——一次普通提问要跑主循环加最多两次核验。

现在：

- `submit_answer` 的 **`answer` 是正文**，按文章写：先给结论，再按需要展开来源说法、背景、有前提的判断与仍不确定的部分。形式由问题决定，不套固定栏目。`facts` 只作为引用账本，承载每条说法依据的已读 `evidence_ids` 与片段。
- **共用阅读协议只对新闻与球队信息生效。** 它规定的是稿件形态、事实条数与修订路径，加载进问答就会把回答变成填表。问答的边界由 `football-assistant/SKILL.md` 承担。
- 原文支持核对把 `answer` 纳入检查范围（此前只核对 summary/analysis/unknowns，正文反而无人核对），并统一以 `summary` 标签呈现给核对器，避免同一段落被重复计费。
- 核验默认关闭（仅新闻稿强制开启），快慢由此前的两到四次模型调用降到一次工具循环。
