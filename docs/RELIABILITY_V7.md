# 看台 V7 可靠性修复

## 使用变化

- 球队选择器直接关注和取消关注，支持搜索、联赛和已关注筛选；查看球队不等于自动关注。
- 模型设置分为“功能分工”和“服务商与模型”。动态整理、足球对话、球队资料解读可以各自选模型，也可以继承默认。无需给同一个服务商重复填写密钥。新增服务商的内部 ID 自动生成，用户只填写显示名称；模型 ID 仍按服务商提供的格式原样保存。
- 对话记录按球队独立保存，显示模型、轮数、时间及完成状态。列表支持分页，详情读取全部已存轮次，不再依赖首页最近 100 条运行。刷新、切页和切队后可恢复；未发出的草稿仅保存在本机浏览器。
- 动态分别显示排队、生成、重试、失败和待配置状态。“刷新来源”唤醒采集与自动队列；“手动整理”使用 `feed` 模型处理点击时本队所有有来源的未完成消息，重复点击去重。不设每次三条或每日十二次额度，后台持续串行处理，结果陆续出现；执行失败或中断如实显示原因，不通过反复消费同一失败请求制造进展。
- 配图仅来自稿件实际引用的文章。栏目分享图和相关推荐图不作为正文配图，同一图片的尺寸或裁切变体去重。来源失效、删除或变为私有时，阅读页不回退旧配图与引用。

## 模型和上下文

| 功能 | 默认角色 | 可见上下文 | 更新方式 |
| --- | --- | --- | --- |
| 中文动态 | `feed` | 该事件固定的来源文章、阅读偏好；不读取个人会话 | 后台采集、重新读取临时正文、整理并核对后保存中文稿 |
| 问助手 | `chat` | 当前球队、当前会话和当前允许访问的来源 | 带入当前范围内的完整已完成对话；历史工具支持分页回读；事实必须重新读来源 |
| 球队与球员解读 | `team` | 当前球队有来源的资料、同一资料解读会话 | 模型解释资料；赛季、成员关系、阵容和比分由数据源维护 |

已有会话固定创建时使用的服务商和模型。改默认或功能分工只影响新任务；删除旧模型后，旧会话历史仍保留，继续时明确提示重新选择。报告后台运行和跟踪任务不会混入个人对话历史，也不能通过父任务指针导入其上下文。

基础工具共 20 类，覆盖球队上下文、来源目录、资料检索、原文阅读、事件时间线、比赛上下文、新闻发现、文章读取、来源采集、工作规程、结构化回答、球员照片、当前会话历史、球队知识、球队结构化资料、球队资料更新、综合研究、阅读偏好、正文定位、来源对照。新闻报告另有 `revise_news`，委派工具另计 6 类；实际提供给模型的工具按比赛范围、文章范围、是否联网收窄，权限仍由执行层检查。

模型自主决定回答的事实数量、章节和详略，用户明确要求的数量优先。不再用默认三项事实、三次联网、八篇原文、固定工具轮数或每日篇数来节省用量；长资料可分页继续读取，同一会话的已保存历史可完整回读。后台保持串行采集与整理，来源权限、实际引用和中断控制继续生效。模型服务自身的上下文与输出容量、单次请求大小及无进展循环保护仍属于运行边界。

## 修复依据与边界

实际失败记录显示，原文核验在固定 45 秒时被取消，而前面的模型响应耗时更长。核验现在至少获得该模型配置的请求时限，同时仍受整体任务时限约束；独立核验不请求额外长思考。未通过核验的事实仍不会发布。

结构化参数错误会指出具体字段和允许长度，单篇文章失败不再使整批综合研究丢弃成功结果。新闻正文仍只在受限内存缓存中暂存，持久保存中文结果、链接及校验信息。

素材已有 96 支球队的本地队徽及出处。2026-09-16 对现有资料的只读检查中，巴萨阵容 29 人有 26 张可追溯照片；曼城阵容 27 人有 1 张。限量补图核查发现曼城官网返回 HTTP 403，两名 ESPN 球员详情均无头像字段，因此缺图仍留空，未推测图片地址或生成真人替代照片。

## 验证方式

自动测试使用临时数据库、MockTransport 和本地模型替身。浏览器验收使用独立 8876 端口及合成资料，检查桌面和 390px 窄屏的模型配置、关注、会话发送与刷新恢复。真实服务商验收只使用隔离数据库副本和有界任务，不写入用户对话。

浏览器验收覆盖中文服务商名称自动生成 ID、手动整理后结果进入动态、无横向溢出和控制台错误，以及私有来源旧卡片不会在展开时重新出现、球队解读草稿刷新后保留模型分工。自动整理与手动整理只保留可追溯的尝试记录，不以记录次数限制新任务。

解除省用量配额后的最终回归：442 项测试与生产构建通过，包含单次 16 条手动消息、105 条自动消息、20 轮工具研究、同轮 21 个工具调用以及 20 条事实完整核验；当前模型输出容量从旧默认 3,000 调整至 16,000。

真实模型验收共两个有界任务。第一轮发现球队大 JSON 中的更新时间与已读片段不一致：30,378 字符的结构导致模型引用未读字段。修复后改用紧凑分段，来源时间置前，单名球员身份、号码和对应采集时间在同一片段，工具不额外暴露未读完整数据。第二轮由现有 `deepseek-v4-flash` 完成两轮工具交互及独立核验，约 20 秒给出有来源的具体答复，核验结果 `supported`，无降级和工具错误。该验证证明当前服务商此路径可运行，不代表所有外部新闻站永远可访问。

升级前数据库及配套密钥保存在 Git 忽略的 `data/backups/`。测试输出、截图、隔离数据库及密钥全部在忽略目录，均不提交。
