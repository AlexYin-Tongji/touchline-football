# V8.7 版式、层次与交互

这一版只改前端样式，不动功能。配色（纸张底 + 墨色 + 印刷红 + 品牌绿）与编辑版设计思路保持原样；业务逻辑、DOM 结构与类名一律未改。

## 改的是什么

用户反馈"字体字号以及排版看着不舒服"，要求"更炫酷，立体或者动态"。

## 一、排版：从 28 个字号召回到 16 档

改动前的实测统计：`v7-app.css` 有 **28 个不同字号**、**15 个不同行高**，其中 `11 / 11.5 / 12 / 12.5 / 13 / 13.5` 六档共 **123 条规则**。相邻档只差 0.5px，肉眼分辨不出，只剩下视觉噪音。

现在收敛成 `:root` 里一套有名字的变量，全套排版从这里取值：

| 变量 | 值 | 用途 |
| --- | --- | --- |
| `--t-overline` | 11px | 全大写小标签 |
| `--t-meta` | 12px | 时间、来源、脚注 |
| `--t-label` | 12.5px | 表单标签 |
| `--t-body-sm` | 13px | 卡片操作、说明文字 |
| `--t-body` | 14px | 界面正文、列表项 |
| `--t-read` | 15px | 摘要、长正文 |
| `--t-lead` | 16.5px | 导读段 |
| `--t-h5` | 16px | 设置面板卡片标题 |
| `--t-h4` | 17px | 四级标题 |
| `--t-h3` | 19px | 三级标题、面板标题 |
| `--t-h2` | 22px | 品牌字、弹窗标题 |
| `--t-card-title` | 26px | 动态卡片标题 |
| `--t-h1` | 30px | 页面主标题 |
| `--t-display` | 34px | 球队页主视觉 |
| `--t-num` / `--t-num-sm` | 27 / 23px | 大号衬线数字 |

行高收敛成 4 档：`--lh-tight:1.4`（大标题）、`--lh-ui:1.7`（界面文字）、`--lh-read:1.9`（长段落）、`--lh-prose:2`（整篇阅读）。

## 二、字体栈换了首选项

`--font-sans` 原本以 `Segoe UI` 开头，中文因此落到 `Microsoft YaHei UI`——雅黑在小字号下字面偏挤、灰度偏浅，14px 的界面正文会发糊。

实测本机 `C:\Windows\Fonts\` 已安装 `NotoSansSC-VF.ttf` 与 `NotoSerifSC-VF.ttf`，`reg query` 确认注册名就是 `Noto Sans SC` / `Noto Serif SC`。把 Noto Sans SC 提到雅黑之前，`Segoe UI` 退到中文之后专门接管西文与数字（它的数字比 Noto Sans SC 紧凑，表格与比分行不会散）。两者都是系统字体，不产生网络请求。

## 三、中文不再按西文排

改动前 `.section-heading` 字距 **2.4px**、`.overline` **2.6px**、`.rail-title > span` **2.2px**、`.brand small` **2.6px**，还都配着 `text-transform: uppercase`——对中文完全无效，是照西文大写字母写的。中文是等宽方块字，字身自带间隙，再叠 20% 以上的字距只会散架。

现在 2px 量级的拉距只留给全大写西文（`.overline`、`.feed-order`、`.club-english`、`.provider-list-heading`、`.team-standings-table th`），中文标签降到 `0.02em`。

## 四、对比度：按最差落点取值

`--faint` 原为 `#9a9386`，在纸底上只有 **2.92:1**——低于大字号 3:1 的下限，而它承载的是 11px 的时间戳与来源名。"看不清"有一部分来自这里。

这一轮把三个次要色都按**它们实际会落在的最差背景**取值，而不是纸底：

| 颜色 | 值 | 最差落点 | 比值 |
| --- | --- | --- | --- |
| `--muted` | `#666e64` | `--paper-sunk` | 4.72 |
| `--faint` | `#756e5d` | `--paper-sunk` | 4.53 |
| `--amber` | `#856b34` | 自身 `--amber-wash` | 4.57 |

来源层级徽标（`.tier-*`）的文字色同样按各自的 8% 淡底核对：`.tier-press` 改为 `#5f6673`、`.tier-community` 改为 `#a04908`。

## 五、层次与立体感

新增四级暖投影，色相取墨色的绿（`#1f2a22`）而不是纯黑——纯黑落在暖纸底上会发灰发脏。另加一层顶部内高光（`--inset-hi`），让平面变成有受光方向的面。

**`.feed-card` 刻意不加 `transform`。** `docs/V7_8_LAYOUT_AND_INTERACTION.md` 记录了约束：上一版用 `translateZ(14px)` 做抬升，卡片被提升到独立图层后盖住了吸顶页头，嵌在下面滚动的内容会从页头下沿透出来。悬停反馈改走"背景浮起"——只改绘制，不建层叠上下文，页头永远不会被压住。

其余元素（侧栏卡片、面板、球员卡、技能卡、选择器卡片）用 `translateY` 抬升 + 投影加深。

## 六、动态交互

全部走 CSS，未改任何组件代码，并统一受 `prefers-reduced-motion` 兜底：

- 动态卡片错峰浮现（`card-in`，前 8 条每档 45ms）
- 侧栏卡片错峰进场（70/140ms）
- 大号数字带虚化落位（`number-in`）——不做逐位计数，数值是数据源给的事实，动画不能改动它
- 导航与筛选标签的指示条从中心展开
- 卡片标题悬停时红线下划线从左生长
- 队徽、球员照片悬停微放大
- 输入框聚焦时红环 + 外圈柔光
- 弹窗背景加模糊，面板带缩放进场
- 底部提示改走独立的 `translate` 属性做居中，把 `transform` 留给进场动画（写在一起会互相覆盖）
- 全站键盘聚焦环统一为红环 + 外圈柔光

## 验证

功能零损耗的依据：`scripts/frontend-regressions.mjs` 的 45 个用例按 `className` 字符串精确匹配。这一版**未改动任何 `className` 或 DOM 结构**，所以改动只可能影响外观。`scripts/class-audit.mjs` 仍报告 342 定义 / 313 使用 / **0 缺口**。

- Python 完整套件 **1319 通过**
- UI 回归 **45 通过**
- `npm run build` 通过
- 桌面 1568px 与窄屏 390px 各 6 个页面（动态 / 球队 / 助手 / 选择器 / 阅读 / 设置）逐一截图复查，无横向溢出

### 核验方式

本项目没有 playwright/puppeteer。为看到界面，临时写了一套离线渲染工具放在 `tmp/styles/`（已被 git 忽略）：用手写的真实类名 markup 加编译后的两份样式表拼成静态页，再用 Edge/Chrome `--headless=new --screenshot` 出图。之所以不依赖后端，是因为 `AuthGate` 挡在 `App` 之前，即使起了服务也只会看到登录页。

过程中实测到两个坑，记录在工具的注释里：headless 的 `--window-size` 有约 504px 下限，请求 390px 只会得到 504px 且媒体查询不按预期触发（`CSS zoom` 也不会移动断点），窄屏检查因此改成把 `@media` 规则体按源码顺序抽出后无条件套用；复用同一 profile 目录的 headless 会留下 `SingletonLock`，导致下次启动在开出 DevTools target 前退出。
