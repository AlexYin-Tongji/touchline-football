# 看台可靠性、性能与可读性优化设计

用户目标：动态采集更快、更少整批失败；球队资料完整性透明；设置页浅色绿色、字体舒适；长期使用不因历史数据堆积而卡顿；测试容易执行维护。优化前 `v7.0.0` 已推送，固定在 `d2f63e0`。按用户偏好只保留 main。

保留现有 React/Vite、FastAPI、SQLite 和三个主入口。工具负责安全网络访问、缓存和结构化事实，应用技能规定先读快照、识别缺口再补充，运行控制负责并发、去重、超时、部分成功和中断。不给模型新增事实写入权限，不重新保存外部新闻全文，不恢复任意每日篇数或研究轮数配额。

新闻：有界并发与同源并发控制，在途请求共享，短失败冷却；成功结果及时保存，失败逐项说明，显式刷新能重试。提取器先确定主文章对象，再取同一对象的标题、正文和日期。固定来源预读允许网络失败的部分成功，权限或范围错误仍拒绝。短周期重复工具结果且无阅读进展时停止。

补充用户确认：多模型协作发生在项目运行时。独立报告最多并行2条，所有角色共用全局3/同服务商2请求上限。增加verify角色，可与生成模型不同；未指定时跟随任务模型，始终以独立上下文核验。任务开始后固定核验模型，排队仅受整体时限约束。

球队：阵容、单队完整赛程和联赛积分分别更新和缓存；照片是可选补全，不阻塞主体。维护工具可指定缺失部分。返回每部分状态、更新时间和覆盖情况，不把空响应当完整球队资料，不用旧快照掩盖新失败。

真实联网发现ESPN API在当前出口403而固定公开网页200，增加公开网页备用适配，只接受可确认的球队、赛季及数值；不绕过登录或授权，不将网页占位score=0用作比分。

界面：浅灰白背景、白色表面、绿色操作强调、中文系统无衬线字体、16px正文与至少14px关键说明。设置区区分功能分工和服务商编辑，390px布局保持可读。修复发送草稿丢失和切队旧请求，模型删除后提供可执行恢复动作。主题筛选在后端先筛后分页。

性能与升级：壳层改用轻量状态接口，非首屏页面按需加载，减少重复轮询；SQLite批量写入采用可回滚事务；迁移前保存一致性数据库及密钥备份。已有服务的构建标识变化须提示安全重启，安装脚本按依赖与构建输入变化更新。

测试：保留安全和数据正确性回归，增加少量针对真实缺陷的用例。快速套件用于日常，模块套件用于局部修改，全量套件用于交付。统一入口打印慢测试和耗时，减少重复种子写入；不以删除仍有效的回归换取数字减少。新增前端异步行为测试，设置页桌面和窄屏真实截图验收。

验收：所有现有测试与新行为用例通过；生产构建通过；Mock延迟场景显示并发且结果稳定；接口大历史数据情况下轻量结果不携带历史正文；维护结果能区分完整/部分/过期；UI在1440px及390px无横向溢出、关键文字可读。真实联网仅限少量公开来源，不调用真实付费模型。报告区分模拟性能与实网观察。
