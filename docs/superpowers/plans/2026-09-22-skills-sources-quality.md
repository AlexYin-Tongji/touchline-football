# 三大技能、信息工具与新闻质量优化计划

用户已要求直接完成优化，并补充新闻正稿应像面向读者的报道。保留当前事实、来源、隐私、比赛范围及完整核验要求；不以缩短文章或放宽核验换成功率。

## 基线

- 代码基线：4db24af（V7.2.0），开始时工作区干净。
- 只读本机运行记录：42次真实新闻整理，33次完成、9次失败；其中8次核验未通过，1次协议响应不合要求。20次进入第二次核验，21次只核验一次。
- 步骤时间差近似：83次模型阶段平均15.14秒、最长51.96秒；61次核验阶段平均3.27秒。该指标不等于独立HTTP耗时，不能直接作为性能保证。
- 实际成稿重复导语、泛化影响与资料缺口；程序强制完整稿至少有analysis或unknowns，推动了无必要内容。
- 当前用户感知约50%不能直接视为这42次样本的客观通过率；分别核对发现、阅读、生成和核验。

## 实施

- [x] 三个标准技能目录team-news/team-information/football-assistant，含name/description YAML；九个历史任务模式通过兼容映射加载对应参考文件，模型主清单只展示三个入口。
- [x] 改善新闻标题、导语、正文、归因与自然段，允许没有额外分析或未知清单的完整新闻；不删重要事实、数字、条件与具体材料限制。
- [x] 核验去重相同引文、合并重叠上下文窗口，完整保留原有证据字符；明确来源元信息和可读范围；修复部分来源完整性串扰。
- [x] 选定资料有界并发读取，保持输入顺序、部分失败保留、权限复核和取消传播；度量串行与并发受控场景。
- [x] 修复等价Unicode转义导致正常长交付参数误拒绝；先验证结构与解析后内容大小，原字段安全上限保持。
- [x] 增加实测可用的BBC全足球和Sky Arsenal RSS，修复Sky BST日期；按目标球队和男足过滤，尊重显式来源名、禁用配置和自定义源；共享公共索引元数据缓存。
- [x] 新来源以公开RSS/普通正文访问为限；不绕访问限制，不添加未经验证的联盟日期，不保存外部原文库。
- [x] 受控质量/效率测试、限量真实来源验证、独立审查、完整Python+前端回归+构建；最终记录实际证据和剩余边界，版本7.3.0、本地提交、不推送。

## 分工

- 根代理：技能路由与提示接入、新闻交付门槛、工具参数、初始资料并发、综合验证与交付。
- scheduler_audit：verification.py及对应测试，核验效率与完整性修复。
- agent_loop_audit：agent_skills三个入口、按需参考与新闻写作例子。
- news_style_baseline（复用）：news_sources.py、research来源相关函数、源接入测试。

## 进度

- 官方规范按agentskills.io的name/description、目录命名和渐进加载执行；运行权限仍由工具代码决定。
- BBC/Sky已由独立调研通过临时Store走实际_source_index与现有代理路径验证。德甲/西甲索引缺日期，本轮不冒称近期覆盖可用。

- 最终检查：574项Python测试、6项前端回归及生产构建通过；独立审阅发现的并发撤权/排队撤权、youth误筛均已补失败用例并修复。
- 本机新来源实际读取BBC 86/86条日期、Sky 20/20条日期；公共索引跨队命中缓存。
- 新文风有同事实虚构样稿审阅，未用真实付费模型进行跨模型评分；不承诺主观分数或将离线提速外推端到端。
